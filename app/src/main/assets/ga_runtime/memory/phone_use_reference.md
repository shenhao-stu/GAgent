# phone_use — 手机 GUI 操作总规程

系统设置优先 GUI：亮度/音量/显示等任务无需为此连接 ADB；亮度可先 `droid.quick_settings()`，用完 `droid.dismiss_shade()`。控件位置和值必须现场读取，不能凭“手势返回 ok”或亮度条标签宣布完成。
两种观察格式不同：`dump()` 的文字键是 `t` / `d`，需要类名和完整边界时 `dump(full=True)`；滑条节点的 `range` 给出 min/max/current，按其当帧 `b` 边界拖动并回读 current 核验。`look()` 才使用 `label` / `cls`。不要用 `label` 过滤 `dump()` 后把缺失键误判为无文字。
可选加速：用户已配置 Jev 时，当前屏幕的单步导航目标可用 `droid.tap_target(target, package=包名)`；首次先读 `memory/jev_phone_use.md`。它只选当前候选，不生成坐标或规划整段任务；无配置保持原流程，目标核验与授权规则不变。
纯 GUI / 微信开局：`droid.launch(包名)` 后先 `print(ask_vision(droid.shot(), "描述当前可交互层：是否有弹窗、关闭按钮在哪里、可执行的下一步是什么？"))`。统一入口为 `droid.ask_vision`；`code_run` 也预导入同一个 `ask_vision`，无需猜模块名；未配置时按 `memory/vision_sop.md` 配置。进入新小程序或点击后页面未变时也先做这一视觉检查。
定位用 `print([(d.get("label"), d.get("cls"), d["x"], d["y"]) for d in droid.look()])`；保留全部紧凑候选，匹配视觉确认的按钮与当帧坐标，再操作。弹窗存在时只操作最上层，不能点击遮罩后正文；不要用 `back()` 猜测关闭弹窗，它可能退出小程序。
微信的 `dump/find/tap_text` 依赖被禁止的节点树，不能用它们判断按钮是否存在；文字按钮也从 `look()` 的 `label` 匹配。`ocr_text` 接受图片裁剪数组，不接受搜索词；`shot()` 返回像素数组，不能打印给模型看或使用不存在的 `save=True`。
常用签名：`tap(x, y)`；`paste(text, replace=False)`（微信仅放剪贴板，必须继续点可见粘贴菜单/键盘候选，不能反复调用当作输入）；`swipe(x1,y1,x2,y2,dur=300)`。浏览下方内容用 `scroll_view('down')`，浏览上方用 `scroll_view('up')`（参数是浏览方向；旧 `scroll()` 参数是手指方向，与之相反）；默认 `frac=0.35, dur=600`，每次观察后再继续。返回/桌面用 `back()` / `home()`；`key('ENTER')` 仅支持回车；没有 `droid.input` 或 `droid.sh`，不调用 shell/广播输入。`look(conf=0.25, roi=None, label=None)` 返回检测框，`label` 按 OCR 文字子串筛选全部匹配项，多命中先消歧，不接受问题字符串；看图问答用 `ask_vision(droid.shot(), "问题")`。roi名称只有 top/upper/middle/lower/bottom，其他区域传矩形元组。普通App的 `find(text)` 返回列表。
排序/筛选必须核验当前选中项和箭头方向，不能凭两条价格恰好递增或返回 `ok` 宣称成功。文字/OCR不显示高亮或箭头颜色时，调用 `ask_vision` 看当前截图；列表不单调不能自行解释为广告。一次点击未生效就重新观察当前可见层与 `look()` 坐标，滚动吸顶后树坐标可能滞后，不连续重用旧坐标。
用户明确要求的导航直接执行，无固定动作预算或解锁步骤。结束前重新观察停点；「去结算」不等于「提交订单」，没有提交授权就停在确认页。

## §-1 开局最短路径（r28 起；130+ 真机 run 统计：开局阅读占 14% 轮数、忘 import 与重复找节点占 15%，这一节就是为了把它们清零）
1. **只读两份**：本文 + `memory/app_cards.md`（各 App 通用操作手册·速查卡，含约束账本三步与设备无关规则）。卡片写「见长档案」或遇到卡片没覆盖的弹窗/风控时，才 `file_read memory/app_scenarios_sop.md` 并只搜该 App 名那一行。`app_ops_sop.md` / `modes_index.md` 不必再读（账本纪律已并入卡片 §A；路由=点名 App 即锁定 App）。
2. **code_run 已预导入 `droid`**（每轮新命名空间，变量不跨轮）：不用再写 `import droid`；找节点用 `droid.find('文字')` / 点节点用 `droid.tap_text('文字')`（多命中会抛出候选让你加 exact/idx）/ 视觉用 `droid.look()`（shot+ui_detect 一步，每项带中心 x,y）/ 尺寸用 `droid.screen()`。别再手写列表推导、别 print 整个截图数组、别猜 ui_detect 签名。
3. **首个 App 动作在第 2 轮**：第 1 轮读两份文件 + `pkgs`/`launch`，第 2 轮就该在 App 里；读完卡片没有任何新事实要确认就不再读别的。
4. **终态即 final**：任务口径满足（约束全核销 / 到停点 / 状态已回读）就立刻 final；不追加浏览、不写记忆管家话、不复述规范。final 第一行写渠道与结论，随后给用户要的字段，最后一行写未落地的约束或前提（如「结算页未选地址」）。
5. **绝不把绝对坐标写进记忆或 SOP**；位置用文字锚点 + 相对位置（顶栏/底栏/第 N 张卡/`screen()` 比例）。

## §0 任务通道决策(先选通道, 再进入 GUI)
0. **App 搜索/筛选/排序/浏览类任务**（用户说「打开某 App 搜/找/筛选/排序/比价」）：按 §-1 读 `memory/app_cards.md` 该 App 的卡（入口锚点/排序筛选位置/停点/风控）并立约束账本（卡片 §A）；卡片没覆盖的 App 或卡片指向长档案时再读 `memory/app_scenarios_sop.md`（逐 App 长档案：冷启弹窗序/风控信号表/§3 剧本），照剧本走, 不从零摸索; 涉及花钱/发送的任务同时守 §0.5 #17「提问预算一次」。
1. 用户指定优先: 明确点名 App/浏览器/Python 时按指定通道。
2. 先过滤无法满足结果/状态/权限需求的通道。
3. 涉及账号状态、本机状态或外部写动作时, 优先选择具备所需能力的已装 App。
4. 无状态公共查询或本地计算(天气、汇率、日期、单位换算等), 从等价通道中选择预计交互轮次最少者; 同轮次优先已装 App。
5. 交互成本计入启动、导航、输入、验证、登录/授权和降级。
6. `pkgs()` 只证明存在可启动候选, 不证明该 App 支持请求所需能力; pkgs() 发现不消耗这一次探测。Google 套件尤其要核对包名：`com.google.android.apps.docs` 是云端硬盘，Google 文档是 `com.google.android.apps.docs.editors.docs`（设备端自演化沉淀, bench v6_note_docs_create 实证: 走错包浪费 3 轮）。
7. 选中 App 后只探测一次: 该探测=launch + 一次初始状态/能力检查; 不存在、能力不足或不可用时降级至 webcdp 或 Python, 不自动安装。
8. Python 仅用于不需要手机 UI 的工作; 不得绕过 droid 操作 App。

选中手机 App 通道后, 唯一 GUI 操作入口 `droid`(files/ga/droid.py, code_run 已预导入, 也可显式 `import droid`)。文档=droid.py docstring; 禁猜接口、禁绕过 droid 拼 HTTP。定位三件套: `find(text)` → 节点(带中心 x,y) / `tap_text(text)` → 唯一命中才点 / `look()` → 视觉检测(带中心 x,y)。
动作只走 droid: tap/swipe/paste/key('ENTER')/back/home/launch(pkg)/pkgs(关键词); 严禁 pm/am/monkey 等 shell 起 app(app uid 无权限)。
定时唤起 agent: `droid.alarm_set/list/del`(到期 call_once 新会话)。用户要起床铃/系统闹钟→系统时钟 App GUI, 勿混用。
与 PC computer_use 同源: UIA↔dump, ljqCtrl↔droid 动作, ui_detect 跨端复用。

## §0.5 行为铁律（131+ 真机 run 实测沉淀; v2.30 自演化备份收编）
通道优先级: dump > adb/intent/settings > webcdp(SOP路径) > 裸HTTP; 视觉只兜底（实测错误率 5%/15-19%/20-32% 递增）。
1. 开局先读 SOP 再动手: §0 通道决策+领域 SOP; 涉账号/本机状态的服务优先已装 App。
2. 登录墙≤2 次即停: 换 App 通道(先 pkgs('站名'))或 ask_user 请人工登录; 禁用搜索引擎 site: 排序冒充站内结果; 拿不到就明说。
3. 改系统状态必状态接地终验: final 前必须有 settings get/dumpsys/content query/文件 stat 级证据; UI 文本"已开启"不是证据; OEM 同名面板(勿扰/专注)≠AOSP 全局状态。
4. 仪表优先: 工具读数与预期矛盾→默认仪表对; 推翻仪表须第二独立通道复核; final 禁止与轨迹内证据矛盾。
5. 重试必须带新信息: 同动作同错误≥2 次→强制根因诊断步(读 traceback/inspect 签名/dump 现场); help/dir/inspect 实测 0% 浪费率, 放心用。
6. 首用 API 先 help()/inspect.signature(): 1 步换 2-8 步。
7. 滚轮/滑杆类脆弱控件一次失败即切 intent/settings put; 切通道前先取消未保存编辑态。
8. shell 三戒: 先 which 再用二进制; dumpsys 带 timeout 且单管道; URL 编码一律 quote() 禁手拼。settings put ≠ 运行时状态(如音量), 写后必读验。
9. tap 前唯一性断言: 候选过滤后 len(top)!=1 即 raise, 绝不点"大概是它"; tap 后核 ping().pkg, 前台包非预期立即 back。
10. 时长关键序列单脚本原子执行: tap(start);sleep(n);tap(save) 在一个 code_run 内完成, 禁跨 turn（turn 延迟 >15s 会污染时序）。
11. 子目标准入: 入队前自问"它改变最终验收吗"; 答案已满足任务口径→立即收敛交付。
12. dump 可用则少用 shot/ui_detect; 视觉仅在 dump 缺目标(SurfaceView/自绘控件)时启用。
13. 约束账本外化: 约束/已证伪路径/勿动项写 checkpoint, 防长轨迹遗忘与复踩。
14. final 引用契约: final 必须引用最后一次独立验证的工具输出(状态读数/新帧证据); 自身动作的 UI 回声(滑块像素动了/面板文案"已开启"/行选中态)不算验证。
15. 惊异观测后先做最小实验: 读数漂移→重写目标值+重读一次即可定位; 禁止信任崩塌式回退已达标状态、禁止无对照的大动作实验。
16. 替代方案枚举必须跨通道: 卡死时候选清单里必须有 web/App/shell 三域各至少一项; 登录态是资产, 已装 App 是登录态的载体。
17. **提问预算 = 整个任务一次, 且只问「不问就会做错」的事**(叫车 case 实证: 41 轮 13 分钟、4 次向用户求助, 0 产出): 出发地默认当前定位、平台默认已装且已登录的那个(先 `pkgs()` 一次全枚举, 不逐个猜)、时间默认现在、车型默认经济; 这些**不问**, 直接采默认并在 final 里声明。唯一必问点 = §0.7 确认门, 把「价格/车型/上下车地点」一并列出让用户一次点头, 不拆成三问。用户说"你决定/别问了"后, 剩余决策全部自决, 卡住也不再问——改报告"做到哪一步、卡在什么、需要用户做什么"然后**结束**, 不循环求助。**问只能用 `ask_user` 工具**——纯文本里列问题 = 宿主视为最终报告, 任务当场结束(v9 train_L4: 读完 4 份 SOP 后用纯文本问了出发城市/会议时间/提醒方式三件事, 0 个 App 动作就结束了)。意图式出行/日程类指令的默认表: 出发城市=当前定位城市(高德/12306 首页默认站), 「上午到」=到达≤11:00 取最早, 提醒=发车/出发前 60–90 min, 车型/座席=二等座——先按默认查出候选, 再在设闹钟/下单这一道门前一次 ask。
18. **开局枚举一次, 后面不重探**: 任务涉及"某类 App"(打车/外卖/快递)时, 第一轮 `droid.pkgs()` 全表 + 一次 `file_read` 相关 SOP, 之后据此选定通道; 禁止逐个 launch 试探(叫车 case: 美团试→无入口, 支付宝→被广告拦, 再美团…)。找不到专用 App 时: 支付宝/高德/美团都内置打车/外卖/快递入口, 按 app_scenarios §2.2 表直达, 不要在首页翻功能页。
19. **输入替换而非追加**: 目的地/搜索词/预填昵称等要**覆盖**旧值时, 用 **`droid.paste(text, replace=True)`**(APK ≥ build 132: 先全选框内文本再粘贴=覆盖; 返回 hit 按「框内 == text」判定, 框不支持选区会直接抛错不会静默追加); 旧版或抛错时才退到 App 自带 ✕ 清除 / 长按全选; `key()` 只有 ENTER 没有退格(叫车 case T36 用 `key('BACKSPACE')` ×30 全部失败; v8-astra 腾讯会议昵称预填 ozer, 默认 paste 追加成「ozerGA测试」)。地址类输入**先按用户原文粘贴**, 候选列表里选**完全匹配**项; 无完全匹配 → 报告"解析到 X, 距离 Y km, 与原文不一致"并停, 不改写地址不换地图选点(T30-31 把 116 号解析成 1080km 外, 正确停手)。

20. **约束逐条接地, 不接地就标注**: 多约束任务(排序方向/筛选 chip/路线偏好/城市限定/价格区间)里**每个约束落地后都要回读页面确认生效**——排序看 chip sel:1/箭头方向+结果首尾单调, 筛选看 chip 高亮+结果字段(城市/时长/评分), 路线偏好看方案标签(「不走高速」=方案卡上有对应标记)——确认不了就换路径, 仍不行则 final **逐条标注哪条约束未生效**, 不要把「筛了但不知生效没」当成功。输出顺序必须跟要求的方向词一致(「从近到远」= 日期升序, v9 show_L2 内容全对却把 10/31 排在 10/5 前面)。城市/本地类筛选常不生效(闲鱼「上海本地」v9 两次), 兜底 = 逐条读卡片上的位置字段再过滤(used_L4 这样做成功)。要「两家/前三」而只核实到一家时, 先扩大候选(翻页/放宽距离)再下结论。v9 重采样 L2(=单 App + ≥3 约束) SR 35%, 低于 L3/L4 的 64%/71%——GA 的短板是**约束密度**不是跨 App 跳数。

### §0.7 确认门(手机端唯一定义; 其它 SOP 写「走确认门」即指本节。旧文引用的 `plan_sop` 在手机上**不存在**且桌面版已弃用——叫车 case T4-T6 因找它浪费 2 轮, 勿再找)
- **门在哪**: 不可逆动作**执行前的最后一步**——支付/下单提交/叫车呼叫/发消息/发帖/删除/装 App/授权他人访问。只读、加购、填表、到结算页、选候选、关弹窗、同意 App 自身的协议与定位权限**不是**门(可自决)。
- **怎么问**: 一次 `ask_user`, 把用户点头所需的全部事实列齐: 对象(店/联系人/车型)、内容原文、金额/预估价、起终点或收件人; `candidates` 给「确认执行 / 取消」。不拆成多问, 不在门之前另问偏好(用默认值)。
- **门之后**: 用户点头 → 只执行**一次**该动作 → 用独立证据核验(订单页/新气泡/车牌/文件存在) → final 引用证据。用户拒绝 → 停在门前, 报告已到哪一步。用户此前已说"你决定/别问"→ 花钱/发送类动作**仍要过这一道门**(那是对路径的授权, 不是对花钱的授权), 其它一律自决。
- **不可越过的门**: App 自己弹的支付授权/免密签约/实名/绑卡/短信验证码 → 永不代点, 交用户(§2.1 风控信号同口径)。

### §0.6 设备知识(按机型分段: 先认机型再套用——`droid.ping()` 不带机型, 用桌面/设置页外观或 `adb_shell('getprop ro.product.model')`(已连 ADB 时)辨认; 不匹配的段落**不适用**)
**Flyme/魅族21**:
- 控制中心磁贴双热区: 图标区=toggle 直接开关; 文字/主体区=进配置面板(勿扰文字区会进"专注模式"面板)。
- 专注模式面板: 行选中+"已开启"文案≠zen_mode 生效; 须点行右侧下拉箭头选时长(如"30分钟"), 状态栏出🌙才算开; 或直接 adb settings 验 zen_mode。
- "显示和字体大小"滑条异步提交: 页面失焦/退出才 commit, 期间 settings put 会被后落地的 GUI 值覆盖; 改字体走 settings put system font_scale X + 回读(前提: 用户已开无线调试), 别碰滑条。
**Pixel / 原生 Android 16**(2026-09-03 bench 实证):
- 系统设置 GUI 路径全部可用且 dump 节点齐全, **优先 GUI, 不为写 settings 去求 ADB**: 字体=设置→显示→「显示大小和文字」滑条(档位 0.85/1.0/1.15/1.3/…, 松手即提交); 亮度=快捷设置滑条或 设置→显示; 媒体音量=音量键/设置→声音; 勿扰=快捷设置「勿扰」磁贴(图标即 toggle)。
- 快捷设置面板用完**必须收起**(`droid.dismiss_shade()`; 旧 APK 用 `back()` 直到 `ping().pkg` 不再是 `com.android.systemui`): 面板残留会变透明层, 之后所有 tap 无响应且 dump 只剩状态栏(app_scenarios_sop §2.2「系统面板」)。
- 首次打开系统 App 会弹 Android 13+ 通知权限对话框「要允许 X 向您发送通知吗?」: 先确认没有面板残留, 再 dump 取「允许/不允许」节点坐标点一次即可(任务无关时点「不允许」)。
- Google 联系人编辑页: 号码框不支持长按全选; 改号码 = 点该号码行右侧「删除手机电话号码」✕ → 「电话」重新添加字段 → paste 新号(v6_contact_edit 实证 29 轮通过)。号码显示会被格式化成「139 0013 9001」, 核验时去空格比。
- Google 日历改时间: 事件详情 → ✏ 编辑 → 点日期/时间行各改一次 → 保存; 用 `content query …/events` 核 dtstart(ms, 按 Asia/Shanghai 折算), 不看 UI 文案。
- 键盘/对话框: `droid.key()` **只有 ENTER**, 收键盘/关对话框用 `droid.back()`。**dataSensitive 对话框**(Files by Google 重命名/删除等, Android 14+ `accessibilityDataSensitive`): 旧 APK 上 `dump()` 只回空壳 FrameLayout、paste「no focused input」、tap 按钮 diff 0% 但点对话框外 scrim 能关——这是 App 对非工具类无障碍服务的定向屏蔽, 不是坐标/时序问题, 换坐标/换手势/OCR 找按钮**全部无效**(v6_files_rename 47 轮实证)。APK ≥ 74eee6d(`isAccessibilityTool=true`)后与 uiautomator 同权: dump 见 EditText/取消/确定, paste/tap 生效。识别特征 = `dump()` 只有无文本容器且 `ping().pkg` 是目标 App → 旧 APK 直接交用户, 不试第 2 次。
- paste 是**追加**不是替换: 重命名/改号码这类"替换原文"场景, 先看框内是否已全选(dump `sel`/视觉高亮), 没全选就 paste 会得到「旧名新名」拼接(v6 复现: `bench_old_x.txtbench_new_x.txt`); 清空用 长按→全选→退格 或 该 App 自带的 ✕ 清除按钮。
- 无线调试默认关闭: 这是用户专属开关, agent 不得自行打开(adb_self_setup.md 红线); Pixel 上凡是 GUI 能做的都不需要 ADB。

## §1 工具选型(GUI 任务先 ping → dump → 再操作)
| 工具 | 时机 | 能力 | 限制 |
|---|---|---|---|
| 0 ping | 始终先行 | 前台包名/a11y/服务状态 | 只判状态, 不定位控件 |
| 1 dump(a11y树) | 控件树可用时优先 | 探测控件+节点坐标, 默认按节点坐标 tap | 敏感 App/风控验证界面=红线禁用(代码层已硬门控: 前台敏感时 `droid.dump()` 直接返回 `[]`, 无需上层判断), 游戏/三方内嵌 WebView=树空壳走视觉(两类细则见表下); 只剩底栏/标题壳=主体无效 |
| 2 shot+ui_detect | dump 空/缺目标/主体无效 | 截图检测控件, 返回 bbox+OCR 文本 | 已带 OCR, 同帧勿再 OCR; bbox=整屏物理坐标, 直接 tap 中心 |
| 3 vision(VLM) | ui_detect 仍不足 | 仅语义理解/确认界面状态 | 不可信其坐标 |
- 🔴dump 风险红线(封号): 敏感 App(清单见 `droid.SENSITIVE_APPS` 注册表——代码是唯一真相源, 本文不复制清单)及已识别的风控/安全验证界面上禁用 dump——读控件树=已成文封号元凶(执行细则见 §5), 只走 shot()+ui_detect/ocr+tap(x,y) 视觉路径。机理: 风险主体是「已启用的无障碍服务(会被枚举上报)+注入式动作+行为模式」, 不只是字面上那次被动读树; 且此类 App 会对读树者返回**故意伪造/投毒的节点数据**——走视觉既收敛风险面, 又不拿假数据行动。**代码层强制(fail-closed)**: `droid.dump()` 检测到前台为敏感 App(或前台未解析)时直接返回空列表 `[]`, 上层拿不到任何节点→只能走视觉; 无需也不该再依赖上层自觉判断。**dump 恒返回 `[]` = 敏感置空信号 → 直接转 shot()+ui_detect/ocr, 勿当"空壳树/真空 UI"反复重试 dump**。
- 第三方 FLAG_SECURE 防截屏(部分金融/腾讯系 App 的登录后页面, 状态依赖非恒黑): a11y 截图不报错而恒返回**纯黑帧**——`droid.shot()` 同前台连续 2 帧黑会显式抛错, 勿再重截。降级链: 该 App 不在 SENSITIVE_APPS→改 `dump()` 节点 bounds 导航(无视觉复核, 关键步骤先向用户确认); 在册→引导用户手动。与 §2 登录浏览器 FLAG_SECURE 同语义, 只是发生在第三方 App。
- dump 树质量降级(非风险项): 游戏(SurfaceView/GL 渲染→无有效 a11y 节点)、第三方 App 内嵌 WebView(节点虚拟化/不可靠)上 dump 常为空壳→直接走视觉。GA 自身网页任务走 webcdp(CDP 驱动内置 WebView), 不读任何第三方 a11y 树——本条仅指**其他 App**的内嵌 WebView; 敏感 App 内的 WebView(如微信小程序/H5)按上条红线处理: 风险源于宿主是微信这类敏感 App 本身, 不在于"WebView"。
- 前台检测: ping/dump 走 getWindows(已排除 GA 自身与输入法); 偶见 pkg=com.ljq.ga 直接重查。GA 悬浮片触摸穿透, 顶部坐标可直接 tap。
- 屏幕宽高、旋转、折叠状态和系统布局都是变量；坐标必须属于定位时的当前帧。纯视觉定位用 `frame = droid.capture()`，将 `frame['image']` 交给 `droid.ui_detect`/OCR/`ask_vision`，按当帧框定位后 `droid.tap(x, y, screen=frame['screen'])`；滑动同样支持 `screen=`。`capture()` 会核对截图尺寸和采集前后旋转；设备派发前再核对，变化则报错，重新观察，不缩放旧坐标猜点击。宽大于高不能代表折叠/分屏状态；180°旋转即使宽高不变也会失效。截图被缩放或裁剪后先恢复整屏物理像素；不同系统的栏、刘海、键盘和弹窗从当帧识别，不复制某型号坐标。旧 `tap(x,y)` 仍可用，但不能替调用者绑定更早的观察帧。

## §2 三种操作屏路由(开工前按任务选对)
| 屏 | 触发/适用 | 驱动 |
|---|---|---|
| 前台 droid | 默认物理屏 app 操作 | dump/ui_detect + tap |
| 虚拟屏 vdisplay | 用户说「虚拟屏/后台跑/别占我屏幕/不打扰」→立即停用主屏 | `import vdisplay`(docstring=SOP, 前置 adb_self_setup.md; 速查=memory/offscreen_sop.md) |
| 内置浏览器 webcdp | 网页/浏览器任务(**默认前台可见**); **用户点名了 App(「用顺丰速运/在闲鱼/打开 12306…」)就不是网页任务**, 哪怕句里有「查一下」——先 App, 官网只做声明过的兜底(modes_index 路由优先级 / app_scenarios §0 #7) | `import webcdp` → open_url(url) → web_scan → web_click/web_type/web_cookies, 每步 web_shot 回图给用户看进度 |
- 虚拟屏模式下主屏 tap/launch/home=破坏用户意图; 仅 vd 明确不可用且已告知用户才降级前台。
- **浏览器三级路由(open_url 默认走 L1 前台, 满足"用户能看见 GA 在操作"的默认期望; 用户没说"后台"就别用离屏)**:
  - **L1 前台内置(默认)** `webcdp.open_url(url)`: 拉起前台任务浏览器 AgentBrowserActivity(用户可见 + droid.shot 可截到 + CDP 可驱动)。绝大多数"用浏览器/打开网页…"任务走这条。
  - **L2 后台离屏** `webcdp.open_url(url, background=True)`: 仅当用户明确说"后台/别占屏/不打扰"才用离屏虚拟屏(不遮挡对话页); 要点/坑=memory/offscreen_sop.md。
  - **L3 视觉兜底** `droid.pkgs('浏览器')→droid.launch(包名)+dump/ui_detect`: 仅当 open_url 两条都 raise(CDP 建连失败/站点反 WebView)才降级。
  - ⚠**词义对照(禁自由解读)**: 「内置浏览器/GA浏览器/App内浏览器」=L1 webcdp(GA 自己的 WebView), **不是**系统自带浏览器(com.android.browser 等); 「不要离屏/不要后台浏览器」=排除 L2, **仍走 L1**(L1 本就前台非离屏), 不等于禁用 webcdp; 只有用户点名「系统浏览器/Chrome/夸克…」才直接 L3 droid.launch。
- webcdp: open_url 幂等就绪并回截图 path(直接引用让对话页内联展示); 与对话/登录 WebView 共享 cookie jar, 登录态自动复用; 只有 connect()/ensure() raise 才退 L3 纯视觉。⚠禁 role='raw'(会连系统 Chrome)。
- 登录墙/验证码/2FA: 请用户点对话页顶栏浏览器按钮进入**登录浏览器**人工登录(进程级共享 CookieManager 自动生效); 该浏览器有 FLAG_SECURE, GA **永不代填账号密码、永不截图它**(droid.shot 前台是它会显式报错——正常, 换 open_url 前台任务浏览器操作即可); 用户说完成后重试并用 web_cookies(域名) 验证。

## §3 输入与发送(粘贴递进 L0→L3, 每级动作后读证据, 确认失败才降档)
- L0 paste: tap 聚焦 → paste(text) → 看返回。hit=True=已确认上屏(dump 或 OCR 命中输入框区), 无需调用方再验; hit=False, uncertain=True=未知(不是失败证明), 必须重新读取当前帧或请用户核对, 禁盲目降档/重复。确认未上屏时文本仍在剪贴板, 按返回 hint 递进。⚠拿到 ime_hint 先点它, 禁未试 L1 就 back(提示条随键盘关闭消失); 禁无新信息连续第3次盲 paste。提速可对多段输入用 verify=False 连发、末段 verify=True 收口, 但 verify=False 永远不能证明输入成功。
- L1 点剪贴板提示条: ime_label 仅是元数据, 不能作为可点击内容目标; 只有 ime_hint 可点击。返回带 ime_hint 时 tap 其 box 中心即整段上屏。提示条=剪贴板更新后键盘顶部数秒内出现的候选条(搜狗/百度带"拆"按钮, Gboard 显剪贴板图标, 样式因输入法而异); 数秒会消失, 消失后重新 tap 输入框聚焦可唤回再看 ime_hint。
- L2 长按输入框→菜单点"粘贴": 键盘/表情面板弹起时先收面板让输入框裸露再长按(文本在剪贴板, 收面板不丢; §6 同理)——面板弹着时输入框上移贴着键盘顶, 长按极易按到键位/表情栏; 长按坐标必须取**当帧**输入框 bbox 中心, 禁记忆坐标; 弹出菜单后按 OCR 文字精定位"粘贴"。
- L3 逐键打字兜底(仅 ASCII/数字): 同一帧 ui_detect 把所需键位坐标一次采齐→连续 tap(键间 0.05~0.1s, 不必每键重新截图)→打完一次性验证。中文禁走此路(拼音候选选字不可控); L1~L3 全败→ask_user。
- ⚠adb_shell('input text ...') 禁输中文(系统 NPE 崩溃); ASCII 也会先进拼音输入法 compose 缓冲(候选栏≠上屏, 点候选易双重上屏), 有 droid.paste 时不用它。
- 发送: 优先 key('ENTER'); 不发→先确认已入框再收键盘→shot+ui_detect 找发送键。⚠发送键常被软键盘遮挡且位置随键盘态/文本长度漂移, 每次重新定位, 禁复用旧坐标。
- ⚠图标密集区(如粘贴键紧邻语音键)按 OCR 文字精定位, 别信 bbox 中心/图标标签(易误点相邻键, 如粘贴误入语音录音)。

## §4 弹窗·防劫持·滚动
- 混乱先 ping+dump 认前台包和实际界面(launch 后可能弹系统选择器如应用分身); 新装/冷启 App 第一帧先查权限/引导弹窗(OCR 找「允许/拒绝/以后再说」)再做正事。
- ⚠顶部(状态栏下约 0.15 屏高内)点击防劫持: 同一轮内重新 dump/shot 后立即 tap(通知横幅随时弹出劫持点击); tap 后 fg 变成非预期 App(尤其微信等聊天类)→立即 back 撤出, 禁在误入界面继续任何点击。
- launch 后 fg 未变≠失败: app 可能被 resume 到遗留虚拟屏/分屏→先 `vdisplay.vd_status()` 或 `dumpsys activity activities` 看 display 归属再诊断, 勿在主屏反复 launch/tap。
- 长按 = swipe 同点 dur>=800。
- ⚠`droid.scroll` 只吃**方向/比例**: `scroll('up'|'down'|'left'|'right', times<=10)`, **不是 `swipe(x1,y1,x2,y2,dur)`**——误当 swipe 传坐标(如 scroll(900,1850,...))会被夹取成少量有界滚动(已护栏防失控狂滑), 要按坐标精细滑请用 `droid.swipe`。
- 滚动优先 `droid.scroll_view('down'/'up'/'left'/'right', times=1)`；方向是浏览方向：`down` 看下方内容，`up` 看上方。scroll_view() 自己负责文本/像素证据；`scrolled=True` 只确认内容变化，不代表目标已找到或动画已结束；`scrolled=False` 且无 uncertain 表示有效证据未见滚动；`uncertain=True` 表示观察失败，必须重新读取当前页面，禁盲目重复。
- 交互目标查找固定使用 `scroll_view(..., times=1)`, 每步后重新 dump/shot 观察再决定下一步; times>1 仅用于明确遍历, 且可能跳过目标。
- 一次过冲就缩小幅度并减速，例如 `scroll_view(direction, frac=0.15, dur=800, times=1)`；参数随当前列表响应调整，不在两个端点反复快滑。重新截图确认当前位置；若节点文字与画面矛盾，该界面改用 `look()`/OCR，不继续沿陈旧节点导航。
- 裸 swipe 端点已夹进安全带；按内容选择幅度与时长，等待手势及动画结束后重新观察，不能用派发返回 `ok` 代表到达目标。

## §5 验证节奏与敏感 App
- 敏感 App 清单与策略 = `droid.SENSITIVE_APPS` 注册表(单一真相源在代码, 本文不复制清单)。这些前台上**读 a11y 控件树(dump)是已成文封号元凶**: `droid.dump()` 恒返回 `[]`(敏感置空信号, 非真空壳树, 勿重试), `paste`/`scroll` 的内部 dump 验证走同一策略漏斗自动禁用, 只走 `shot()`+`ui_detect`/`ocr`+`tap(x,y)` 视觉路径。此时 paste 无 edit 框锚点, 常返回 `uncertain=True`——按本节停下用 shot+ui_detect 人工核对是否上屏, **禁盲目重试或据 uncertain 降级**。定位/找目标一律 shot+ui_detect, 严禁 dump/按节点坐标 tap。
- 敏感 App 状态机: `探测 → 单一动作 → 条件等待 → 验证 → 下一步`。
- 同一目标第二次失败后停止重复该路径，读取新截图诊断；可改走画面上已确认的另一 GUI 入口。验证码、登录失效、账号异常则终止整个任务。
- 外部提交前, 目标上下文、唯一载荷和输入确认必须同时成立。只提交一次; 仅在后置条件“输入框清空 + 精确的新气泡/状态”成立后结束。
- 遇到登录失效、账号异常、验证码、安全验证、设备证明或其他风控/反制页时立即停止自动化; 不自动重试、不切换输入法、不使用 ADB 文本注入、不转交厂商助手、不自动登录。
- 不得使用随机抖动、拟人化或隐藏自动化; `human=True` 只提供小幅动作容差, 不改变上述边界。本条取代旧记忆「随机延时降指纹」建议——不做时序伪装; 敏感 App 的残余时序风险靠**减少动作总量 + 必要时人工**承担, 不靠掩盖自动化痕迹。
- 微信等在册 App 只走截图/OCR/可选YOLO和坐标GUI，不读取控件树、节点点击或通知回复。正常任务没有固定动作次数或解锁要求；历史 sensitive_unlock 调用兼容为空操作。每步观察确认；提交订单/发送/支付仍遵守 §0.7。验证码/实名/账号异常立即终止。
- 微信文本输入：`paste(text)` 仅设置剪贴板，返回 `needs_gui_paste=True`，**尚未输入**。根据新截图长按输入框（`swipe(x,y,x,y,dur=700)`）并点击可见的「粘贴」，或点击键盘剪贴板提示；替换先点可见清除/全选。搜索/回车点击画面上的键盘按钮，不调用 `key('ENTER')`。输入后OCR核对。

- 新界面先只探测不操作: ping+dump(必要时 shot+ui_detect), 读完实际输出再决定下一步。
- 一步一验: 明确一个操作→同轮执行→短暂等待→ping+dump/ui_detect 验新状态; 状态无变化立即停下诊断, 禁盲目重试。
- ⚠禁在未知状态把多步决策写进大脚本; vdisplay/webcdp 同样成立——反馈通道越窄(只剩截图)越禁。
- ⚠禁预测关键词筛候选; 看 dump/detect 实际输出、坐标、层级和上下文判断。
- dump 可用则少用 shot/ui_detect; dump 不可用则该界面后续不用 dump。
- 临时截图/可视化禁写项目根目录; 统一写 agent temp/scratch 或固定文件名覆盖, 用后清理。

## §6 聊天类 App 发消息/发图(微信等; 禁固定坐标; 微信另守 gandroid-wechat-yolo 红线)
- 底部输入栏先辨态再操作(语音态/文字键盘态/表情态); 键盘或表情面板弹起时禁长按输入框(易误触表情栏/语音浮层), 先收面板让输入框裸露。
- 发送核验: 输入框清空 + 会话底部出现刚发内容的气泡; 任一不满足即停下诊断, 禁盲目连点。
- 发图: 本地图先写系统相册并确认存在且大小非零 → 回默认输入态 → 视觉定位「更多/加号」→「相册」→ 选目标缩略图 →「发送」。核验=回到聊天页+图片气泡; 仍在相册页/无气泡→先截图认状态, 禁无新信息重复点击。
