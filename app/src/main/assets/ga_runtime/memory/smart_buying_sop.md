# 智能购物/比价 SOP — 全平台通用购物决策

> 核心洞察：**所有购物 App 都是信息差游戏——归一化比价 → 双通道交叉验证 → 按平台性质选成交策略。**
> 动作 API（webcdp/droid）以 droid.py docstring 为准、用法见 `phone_use.md`；操作纪律（约束账本/登录墙/只读）见 `app_cards.md`；信源甄别见 `search_source_sop.md`。本文件只管**购物领域决策逻辑**。

---

## 双维决策模型

```
品质↑
 优 │ 🟢高性价比(最优买点)   🔵品质溢价(不差钱)
 中 │ 🟡临界(需核验)         🟠品牌溢价
 低 │ ⚫临期/瑕疵(低价有代价) 🔴性价比差(别买)
    └───────────────────→ 价格 低→中→高
```

**性价比系数 = 品质分 / 单位价格。** 品质分来源随平台不同：B2C(生产日期+店铺信誉+销量) / C2C(卖家信用+成色+发布时间) / 社交电商(达人+种草) / O2O 生鲜(时效+保质期剩余)。

## Phase 0：通道选择

| 条件 | 通道 | 理由 |
|---|---|---|
| 批量数据采集 / 仅搜索查看 | `webcdp` 网页版 | 一次抓 50+、可 JS 批量、中文直接 `open_url('?q=中文')` |
| 下单/登录/私聊议价 | `droid` App 端 | 登录态完整、可操作按钮 |
| 网页版被反爬/需登录 | 立即切 `droid`，不死磕 | 试一次不行就换 |

> 黄金法则：先 webcdp"侦察"扫全貌，再 droid"攻坚"做操作。**试一次不行就换，不反复重试同一方法。**

## Phase 1：信息采集（通用）

- **多关键词交叉**：≥3 个同义词（`纯甄酸奶`→`纯甄 牛奶`→`蒙牛纯甄`；闲鱼加 `纯甄 全新`/`纯甄 临期`）。
- **最低样本**：≥20 条有效商品（不够就滚动加载或换词；`droid.scroll_view("down")` 每次看下一段，见 `phone_use.md`）。
- **采集维度**：价格 / 规格数量 / 单位价格(核心) / 生产日期 / 销量热度 / 店铺卖家 / 优惠。
- **市场基准**：采集后算 `均价 / 中位数 / 核心区间(25%~75% 分位)`。
- **交叉验证**：webcdp 扫描(全但可能截断) × droid 界面(准但每屏少) 至少两源对价。
- 跨平台：淘宝/闲鱼 webcdp 好用；京东网页常反爬→用 `com.jingdong.app.mall` App；拼多多多需登录；都不行→百度间接查价区间兜底。用户指定 App 时先用该 App；未指定时按 phone_use.md 选择能满足约束的渠道。搜索摘要仅作线索，不当作已核实成交价。（各 App 真实包名见 `app_cards.md` 快查表）

## Phase 2：性价比分析

### 2.0 品类识别（先识别再套模板）

关键词/标题匹配 → `生鲜水果 | 乳制品/标准品 | 数码3C | 服饰鞋包 | 日化洗护 | …`。不同品类维度不同：

| 品类 | 核心规格 | 品质维度 | 归一化基准 | 物流影响 |
|---|---|---|---|:-:|
| 标准品(酸奶/洗发水) | 重量 g/ml | 生产日期 | ¥/g 或 ¥/盒 | 低 |
| 生鲜水果 | 重量斤/kg + 果径 mm | 等级(一级/特级) | ¥/斤@同果径 | 🔴 高(5~15元) |
| 数码3C | 参数对标 | 全新/翻新/官换 | ¥/性能分 | 低 |
| 服饰 | 尺码+材质 | 品牌级次 | — | 中 |

> 不确定维度时先做品类识别再套模板；模板持续扩展。生鲜要点：果径归一化(80/85/90/100mm)、等级体系、¥/斤 归一、运费计入总价、时令(7月洛川富士=去年冷库果品质打折)、地理标志真伪。

### 2.1 单位价格归一化

不同规格必须归一到同一基准才可比：
```
"200g×24盒 ¥69.32" → ¥2.89/盒 ; "200g×16盒 ¥33.90" → ¥2.12/盒 ← 更划算
基准优先级: 每单位数量(盒/瓶/袋) > 每重量(g/kg) > 每容量(ml/L)
```

### 2.2 临期判断模型（B2C 生鲜食品）

时间基准=今天。假设保质期 180 天：当月~前2月(≥120天)🟢正常价；前3月🟡正常价；前4月🟠打折才买；前5月🔴≤7折考虑；前6月+⚫过期不买。

> 临期不是坏东西：能在保质期内吃完，临期可能是**性价比之王**(5~7折)。

### 2.3 综合评分
```
性价比 = (品质分×权重 + 价格分×权重)/2 ; 价格分 = 市场均价/该商品价
品质分(B2C): 新鲜批次100 / 常规80 / 临期50 ; 旗舰店 +10 ; 有券/百亿补贴 +10
品质分(C2C): 近7天发布100 / 7~30天80 / 30+天60 ; 高信用 +10 ; 可议价 +5
```

## Phase 2.5：偏好问询（重要！中间环节交互）

> **发现重要偏好维度时，必须先问用户，再给结果。** 这是本 SOP 的关键交互点。

### 防漏检红线：完整扫描所有偏好维度，禁止主观跳过

必须对商品集执行**偏好维度扫描**，逐维检查是否存在差异：
```
☑ 临期/日期(任何商品都查, 禁"保质期长不用查")
☑ 规格/容量    ☑ 价格区间(低/中/高)    ☑ 店铺类型(官旗 vs 普通)
☑ 口味/香型/颜色    ☑ 新旧状态(全新/翻新/官换)
```
> 曾犯错：`"洗发水保质期长不用查临期"`→漏了；`"数码没新鲜度问题"`→漏了(翻新/官换有别)。**不确定某维度是否重要时，先问用户再判断——宁可多问，绝不漏问。**

### 交互规则（核心）

```
Phase 2 分析后, 若存在重要偏好维度:
  ask_user("我发现这批商品可分类讨论, 您偏好哪一类?",
           candidates=[选项A, 选项B, "随便/都看看"])
        │
   ┌────┴─────────────────────────┐
   用户明确选了 A/B           用户选"随便" 或 未回复/未明确
        │                              │
   按其偏好进 Phase 3        最终结果给出【分类讨论】(不替用户拍板)
```

> 用户提出的"随便"= 不替他做主 → **最终结果按维度分类呈现各自的最优解**，让用户一眼看到每一类的性价比之王。

### 输出格式（用户选"随便"/未选时 → 分类讨论）

```
┌─ 🟢 非临期推荐(日期新) ─────────┐
│ 商品A ¥XX/盒 (7月产, 旗舰店)     │
│ 商品B ¥XX/盒 (6月产, 销量20万+)  │
├─ 🔴 临期捡漏(价格优势) ─────────┤
│ 商品C ¥XX/盒 (3月产, 约5折)      │
│ 商品D ¥XX/盒 (2月产, 约4折)      │
└──────────────────────────────┘
```

> 为什么必须问：临期对 A 用户是宝藏、对 B 用户是雷区——不问偏好就推荐＝盲人摸象。用户答"随便"时用分类讨论把选择权还给他。

## Phase 3：购买决策与执行

- **B2C(淘宝/京东/拼多多, 明码标价)**：找隐藏优惠(百亿补贴/秒杀/满减券/会员价)。决策：单位价≤中位数×0.85→✅直接下单；≤中位数→👍可入；>中位数×1.15→⏳找优惠或换店。
- **C2C(闲鱼/转转, 可议价)**：识别卖家策略→反向定价→有据出价→制造紧迫→成交判断(市场价±10%合理, ≤85%果断入)。
- 只读比价任务停在结果页即可（见 `app_cards.md` 只读纪律）。

## 避坑速查

| 陷阱 | 解法 |
|---|---|
| 被"5折/限时"冲昏头 | 先算单位价再比市场基准 |
| 只看总价不看规格 | 归一化到单位价再比 |
| 被划线原价锚定 | 只看单位价与市场基准，无视划线价 |
| 忽视生产日期 | 临期模型必用 |
| 网页与 App 数据不一致 | 交叉验证，操作以 App 端为准 |
| 粘贴失败不自知 | 检查 `paste()` 返回 hit，失败就换策略 |
| 滚动加载不全 | 至少滚 3~5 屏覆盖足够样本 |

## 反套路 × 防 AI 投毒（购物专项）

- 电商话术："原价¥199现¥69"=锚定(看历史成交价)；"已售10万+"=可能累计(看评价时间分布判刷单)；"旗舰店"=同款第三方可能便宜 20%。
- 闲鱼："自刀出"=虚构原价(搜同类均价参照)；"女生自用几乎全新"=通用话术(看历史评价+对话试探)。
- AI 投毒：AI 评测(语气空洞/无实物图)、AI 商品描述(关键词堆砌/夸大功效)、AI 买家秀 → 要实物图/搜"差评"/问具体问题(瓶底生产日期在哪)。
- 详见 `search_source_sop.md`（信源分级 + 三源交叉 + 投毒指纹通用方法论）。

> 一句话：**归一化比价 → 双通道交叉验证 → 按平台性质选成交策略；发现偏好先问，用户说"随便"就分类讨论。**
