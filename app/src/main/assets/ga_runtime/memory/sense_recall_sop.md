# 记忆回忆与拒答 SOP (sense_recall) — 相对时间转绝对区间, 时空人硬过滤优先, 无证据必须拒答

> 由 `sense_sop` 指路, 不进 `modes_index`。**本能力默认关闭**: 回忆只能命中已经采过的时段, 没开过采集就一定没有记录。
> 铁律: **无证据不作答**。记忆助理编一句「你那天说过 X」, 比答不出来危险得多——一次就把信任烧光。

调用方式与 `S()` 帮手见 `sense_sop` §1。`sense.recall(q)` 是本文三步(解析→硬过滤→充分性判断)的固定序列; **用它也必须自己复核 `evidence`**, 别把 abstain 判断外包出去。

## 1. 相对时间 → 绝对区间(第一步, 不可跳)
一律用**设备当前时间与本地时区**, 禁止用模型自以为的"今天"。区间左闭右开、单位毫秒。

```python
import datetime as dt
PART = {'凌晨': (0, 6), '上午': (6, 12), '下午': (12, 18), '晚上': (18, 24), None: (0, 24)}
def span(day, part=None):                     # day=date 对象 → (t0_ms, t1_ms)
    b = dt.datetime.combine(day, dt.time())
    h0, h1 = PART[part]
    return (int((b + dt.timedelta(hours=h0)).timestamp() * 1000),
            int((b + dt.timedelta(hours=h1)).timestamp() * 1000))
def last_week(wd):                            # wd: 0=周一 … 6=周日
    t = dt.date.today()
    return t - dt.timedelta(days=t.weekday() + 7 - wd)

t0, t1 = span(last_week(2), '下午')            # 「上周三下午」
```

| 表达式 | 规则 |
|---|---|
| 今天 / 昨天 / 前天 | `dt.date.today()` 减 0/1/2 天 |
| 本周三 / 上周三 | 自然周(周一起)。**「上周三」= 上一个自然周的周三**, 不是「最近一个周三」 |
| 上个月 / 这个月 | 月首 00:00 到次月首 00:00 |
| 上午 / 下午 / 晚上 / 凌晨 | 按上表小时段; 「昨晚」跨零点 = 昨天 18:00 到今天 06:00 |
| 刚才 / 刚刚 | 最近 30 分钟; 「刚开完的那个会」用最近一次 session 的实际起止, 别用整点 |
| 上次 / 那次 / 有一回 | **不要猜时间**: 不加时间过滤直接查(默认就是新→旧)取首条命中, 把命中的绝对时间回报给用户确认。传 `order:'ts'` 是**正序**(旧→新), 用它会拿到最早那次 |
| 完全没有时间线索 | 默认最近 7 天, 并在答案里明说用了这个默认 |

自检两条: 算出的区间**落在未来** = 一定解析错了, 停下来追问; 表达式有两种合理解释(如只说「周三」)也追问, 别赌。

## 2. 硬过滤顺序(按序施加, 不可倒置)
`1 时间(from/to) → 2 地点(near/place) → 3 人(with[]) → 4 kinds → 5 最后才是 q`

「某时某地和某人聊了什么」本质是**过滤问题不是相似度问题**。先做语义检索再筛时间, 会把别的时间的相似内容顶到前面——这是记忆产品最常见的编造来源。`q` 为空完全合法: 只按时空人取全量反而更可靠。

```python
plc  = next((p['id'] for p in S('/sense.place list')['places'] if p['name'] == '公司'), None)
peer = next((p['id'] for p in S('/sense.peer list')['peers']  if p['name'] == '老王'), None)
# 名字对不上 → 别硬猜坐标/别模糊匹配: 要么问用户是哪儿/是谁, 要么去掉该过滤并在答案里声明"没按地点(人)筛"
r = S('/sense.query', **{'from': t0, 'to': t1, 'near': {'place': plc}, 'with': [peer],
                         'kinds': ['asr.text', 'note.user'], 'q': '报价', 'limit': 50, 'order': 'ts'})
```

`as_of` 只在自测/复盘时用(只返回 `ts_ingest <= as_of` 的记录, 保证时间因果性), 正常问答不要传。

## 3. 证据充分性 → 答还是不答
先读 `r['evidence']` 与 `r['abstain_hint']`, **再**决定说什么:

| 情形 | 处置 |
|---|---|
| `abstain_hint` 为真 | 先报缺口, **不给结论**; 最多给「我只采到这些」的部分事实 |
| `n_hits==0` 且 gaps 覆盖整段 | 「那段时间我没在记录/被静音, 所以没有记录」——**禁止**说成「没发生」 |
| `n_hits==0` 且 gaps 为空且 `span_covered_ms` 接近区间长度 | 唯一可以说「没聊到」的情形, 且必须限定「在我采到的记录里没有」。**问谈话内容时必须带 `kinds:['asr.text']` 再看这条**: 不带 kinds 时覆盖率答的是「有没有在采集」, 带上才答「麦克风开没开」(只开位置的会话会回 `source_off` 缺口) |
| `n_hits>0` 且 gaps 非空 | 先答已有证据, 紧接着列出缺口区间与原因, 不许省略 |
| `n_hits>0` 且 gaps 为空 | 正常作答: 原话 + 绝对时间 + 地点 + 说话人(按 §4) |

`evidence` 里出现 `l0` 字段 = 有会话窗还开着、但此刻问不到采集服务: 覆盖只按**已经落盘的数据**算, 那段"窗开着"的时间会如实成 `not_capturing`。这时不许说「没聊到」, 只能说「那段我说不准有没有在记录」。

`gaps[].reason` 对用户的说法(照抄, 别自创模糊措辞; 表里没有的 reason 原样念出来并说明「这是原始故障码」, 不要猜):

| reason | 对用户怎么说 |
|---|---|
| `not_capturing` | 那段时间没有在记录 |
| `source_off` | 当时在记录, 但这一路信号没开(如只开了位置没开麦克风) |
| `silenced` | 麦克风被别的应用或系统占用, 只录到空白 |
| `in_call` | 当时在通话中, 系统不允许应用录到通话内容 |
| `all_zero` | 录到的是连续空白(多半被抢麦或系统麦克风总开关关着) |
| `quota` | 达到本次会话的存储上限, 之后没有再录 |
| `io` | 写文件失败, 那段没落盘 |
| `service_gone` | 采集服务被结束了(系统省电策略或任务管理器) |
| `asr_failed` | 录到了但转写失败, 所以没有文字 |
| `retention` | 音频已按保留期滚动删除(转写文本可能还在) |
| `blob_missing` | 那段音频文件已经不在了(多半已过保留期), 所以没有原文 |
| `purged` | 已按你的删除请求清掉了 |
| `cleared` | 手机缓存被整体清理, 那段数据没了 |

## 4. 说话人归属(只认两种锚点)
- `peer_self` = 机主, 唯一可以直接断言的说话人。
- 用户**标注过一次**的 peer(`name` 非 null) → 可以用这个名字。
- 其余一律说「另一位在场的人」。`asr` 的 `spk`(s0/s1)只是**本次会话内**的临时编号, 跨会话不可比, 绝不当身份用。
- 跨天归并只信已配对设备与日历参会人; `near` 里 `stable:false` 的条目跨天不可匹配(设备地址随机化), 这是技术事实, 不要试图绕过。
- 日历 `attendees` 只证明「被邀请」, 不证明「在场」, 更不证明「说了话」——三者措辞必须分开。
- 名字不确定就问一次并落 `/sense.peer name`(顺手定 consent), 比猜一次划算得多。**全自动真名识别一律不做。**

## 5. consent 硬过滤(检索层已过滤, 不许绕)
- `consent=='none'` 的 peer: **只返回存在性**(「当时还有一位在场」), 不引原话、不给转写细节。不得改从 `/sense.blob` 或原始 `audio.seg` 绕过去拿。
- `consent=='granted'` 才能引原话; `peer_self` 恒为 `self`, 机主自己的话可以引。
- 用户说「把老王那段念给我听」而其 consent 是 `none` → 明确拒绝并说明理由, 引导用户在取得对方同意后改 consent(见 `sense_privacy_sop`), 不偷偷放行。
- 这层过滤在**出设备之前**就生效: `none` 的原文根本没上行到 PC(`/sense.sync push` 只送存在性), 所以「去电脑上查」也查不到, 别这么建议; 用户改成 `granted` 后下次同步会自动补推原文。
- 带 `q` 的检索**不会命中**未授权者的内容(否则逐词试探就能把原文猜出来): 所以「搜不到」不等于「他没说过」。要看存在性就去掉 `q`, 只按时间/地点/人查, 拿到的是「当时有一位在场且有记录」这一层事实。

## 6. 答案形状(必须给绝对时间, 让用户能核对)
```
有证据: 2026-08-05(上周三) 14:03 在「公司」和老王: “……报价我们按 12 万走。” (来源: 转写, 置信 0.9)
有缺口: 找到 3 条; 另外 14:10–14:22 这 12 分钟没有记录(麦克风被其他应用占用), 那段说了什么我不知道。
无证据: 上周三下午我没有采集记录(那天没开始记录), 所以这个我答不了。要现在开始记录吗?
```

## 7. 禁止清单
- 禁止把 `evidence` 里没有的内容写进答案, 包括「合理推断」和「大概率是」。
- 禁止把「没采集到」说成「没发生」; 禁止把「没检索到」说成「不存在」。
- 禁止用位置/日历反推「他一定说了 X」。
- 禁止跨区间借证据(拿上周的原话答这周的问题)。
- 禁止在没有 `place_id` 命中时, 用坐标附近的地名冒充用户口中的地点名。
- 禁止把摘要当原文引; 原文只能取自 `asr.text` 的 `text` 字段。
- **找不到就说找不到是本模式的合格线, 不是失败。**
