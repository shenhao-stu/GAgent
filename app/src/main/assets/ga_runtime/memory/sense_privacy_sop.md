# 记忆隐私与治理 SOP (sense_privacy) — 默认关闭/告知在场者/consent 分级/purge 两步与回执

> 由 `sense_sop` 指路, 不进 `modes_index`。调用方式与 `S()` 帮手见 `sense_sop` §1。
> **本能力默认关闭**: 没有正在跑的 session 就是没在采集; 每次采集都必须由用户当次显式动作开启。
> 本文写的是**不可协商的产品约束**, 不是可勾选的设置项。与用户诉求冲突时, 以本文为准并把理由说清楚。

## 1. 唯一真正的法律风险: 同场第三方
用户能同意被记录, **被录到的对方不能**。这是本能力唯一无法用技术绕开的风险, 也是所有护栏的由来。
- 有第三方在场 → **先告知, 再 start**(话术见 §3)。有人反对就不开麦, 改走零录音档(只 `loc`/`near`/`cal`)。
- 中途有新人加入 → 再告知一次, 或当场降到零录音档。
- 声纹/谈话内容属敏感个人信息, 各法域对录音的单方/全方同意规定不同; GA 只负责把告知与标注做到位, **绝不提供规避建议**。

## 2. 默认值(出错时的方向不可反)
读不到 kv、字段缺失、解析失败 → 一律退到本表, 绝不退到「采得更全」。

| 字段 | 兜底默认 | 含义 |
|---|---|---|
| `uplink` | `text_only` | **音频不出设备**; 改 `text_and_audio` 必须用户显式同意 |
| `retain_audio_days` | `3` | 音频滚动删除; 想留更久由用户显式设 |
| `retain_text_days` | `365` | 转写文本保留期 |
| `loc_mode` | `stay` | 只记停留点, 不做连续轨迹追踪 |
| `peers_allow` | `["peer_self"]` | 默认只有机主的内容可被检索到原文, 也只有它会带原文上行到 PC |
| `seg_ms` / `vad_rms` | `300000` / `0`(不门控) | 采集粒度, 真机可调; 在 `session start` 时下发给采集服务, 改完要重开会话才生效 |
| `near_period_ms` / `quiet_apps` / `quiet_places` | `600000` / `[]` / `[]` | **本轮只存不生效**(端上没有周期扫描/静默判定的执行体): 设得下但不会改变行为, **绝不能对用户说「在微信里/在家时不会采集」** —— 要静默就停会话 |

```python
S('/sense.policy get')                                   # source 为 'default' 说明正在用兜底值
S('/sense.policy set', uplink='text_only', retain_audio_days=3, loc_mode='stay')
```
改策略前把**改动的实际后果**用一句话讲给用户(如「音频会留 30 天而不是 3 天」), 再改。

## 3. 会前告知话术(可直接复制给用户念)
中文:
> 「我在用手机上的助理给这次谈话做文字记录, 内容只存在我自己的手机和电脑上, 不会上传给第三方。谁不方便的话我现在就关掉。」

English:
> "Heads-up: I'm keeping a written record of this conversation with an assistant on my phone. It stays on my own phone and computer and is not uploaded to any third party. If anyone would rather I didn't, I'll turn it off right now."

规则: 用户念完(或明确表示已经告知)再 `session start`; 用户说不方便念 → 不开麦, 走零录音档。**不要替用户判断「这种场合应该没关系」。**

## 4. consent 分级(检索层的硬过滤依据)

| 档 | 含义 | 检索层后果 |
|---|---|---|
| `none` | 默认。未同意/未确认 | **只保留存在性**(「当时还有一位在场」), 不返回其原话 |
| `self` | 机主, `peer_self` 的保留档 | 可引原话 |
| `granted` | 对方当面同意过, 由用户设置一次 | 可引原话; 撤回 = 改回 `none` 并按需 purge |

```python
S('/sense.peer name', peer_id=pid, name='老王', consent='granted')
```
- **agent 不得自行判定 `granted`**: 只有用户明确说「他同意了」才写, 且要提示这条同意会被记录下来。
- 不得用 `/sense.blob` 或原始 `audio.seg` 绕开这层过滤(见 `sense_recall_sop` §5)。模型听得懂 ≠ 会自律, 所以过滤放在数据层。
- 采集层产生的行(`audio.seg`/`asr.text`)可能没把同场者标全: 检索层会**回到会话级同场者再判一次**, 会话里有未同意的人就按未同意处理。所以「这条没标人」不等于放行 —— 这是有意从严, 别把它当漏洞去绕。
- 这层过滤同时管**出设备**: `none` 的原文不上行到 PC(push 回 `held_consent` 计数), 改 `granted` 后下次同步自动补推。
  但**改回 `none` 撤不回已经上了 PC 的那部分** —— 那要走 §6 的 purge 才算真删; 别把「改回 none」说成「撤回了」。

## 5. 采集指示不可隐藏
Android 12+ 状态栏麦克风绿点、前台服务常驻通知(带「停止记录」按钮)、A13+ 任务管理器里的服务条目——**三处露出是平台强制的**, 无 root 不可隐藏, GA 也不做任何低调化(通知走 IMPORTANCE_LOW: 不响铃, 但常驻可见)。
用户问「能不能悄悄录」→ 明确回答做不到, 解释这三处露出即可; **不要给任何绕过方案**。产品叙事是「明示的随身记录仪」, 不是「偷偷录」。
悬浮窗当前**不**参与采集指示(未实现), 别对用户说「悬浮窗会变红」——承诺一个看不见的指示灯, 比没有指示灯更糟。

## 6. purge: 两步确认 + 回执
```python
c = S('/sense.data count', **{'from': t0, 'to': t1})     # 第一步: 预览到底删什么
# 把 c['n'](条数) / c['blobs'](音频个数) / c['span'](覆盖时段) 念给用户, 拿到明确「确认删除」
p = S('/sense.data purge', **{'from': t0, 'to': t1, 'confirm': c['confirm'], 'cascade_pc': True})
```
- `confirm` token 只能来自**本次** count: 不复用、不硬编码、不跨 selector 借用。
- selector 与 `/sense.query` 同形 —— **能查到的就能删掉**, 口径一致才谈得上可验证。
- 回执 `p['receipt']` / `p['receipt_path']` 给用户, 这是可自证的凭据。
- 级联给 PC 的永远是**手机这次真删掉的那批 id**(不是把 selector 再解释一遍), 所以两边删的必然是同一批; 只有「一个选择键都没给」的整库清空才会发 `all`。
- `p['pc']['cascaded']` 为假 → 如实说「手机上已删, 电脑上还没删, 已排队等 PC 上线」, 有 `p['pc']['reason']` 就把它念出来(如 `badop`=电脑端版本还不认这种删除请求, `pc_unreachable`=没连上)。**绝不说「已删干净」**——这条诚实度直接决定隐私叙事能不能成立。
  排队不是说法而是真队列: 下次 `/sense.sync push` 会真去补删并回 `purge_queue_flushed`, 欠账笔数随时可查 `S('/sense.sync status')['purge_queue']`; 用户催的时候就当场跑一次 push 给他看数字归零。
- purge 是真删文件不是标记删除; 删完再 `count` 一次复核 `n==0` 再回复用户。
- 被删区间在时间线上会留下 `reason='purged'` 的缺口, 之后回忆会如实说出来——这是特性不是 bug。

## 7. export 与保留期
```python
e = S('/sense.data export', **{'from': t0, 'to': t1, 'fmt': 'jsonl'})   # 产物落 temp/ 下用户可见路径
```
- 导出文件含敏感原文, 提醒用户妥善保管。
- 保留期**不会自己到点就删**(端上没有常驻清理进程, 别对用户说「到期会自动删」): 实际清理动作是
  `S('/sense.blob purge', older_than_days=3)`(音频, 同时留一条 `retention` 缺口)与 `/sense.data purge`(文本)。
  采集收尾或用户问起时看一眼 `S('/sense.blob list')` 的 `expires_at`, 到期的**先问用户要不要延期/先导出**再删。
- 用户问「你都存了我什么」→ 用 `count` + `export` 如实给全集, 不做选择性展示。

## 8. 对外表述红线
- **在能力真正跑通之前, 不得对用户或对外承诺任何隐私能力**(同类产品先宣布后跳票已引发虚假宣传指控)。
- 不用「完全私密」「绝对不上传」这类绝对化措辞。可以说的事实: 默认只有**机主与已同意者的转写文本**经点对点通道到用户自己的 PC(未同意同场者只上行「当时有人在场」), **音频默认不出设备**, 数据可导出可真删。
- 不把「默认关闭」说成模糊的「可选开启」; 不把「部分可用」说成「已全部记录」。
- 不承诺分钟级到达提醒、不承诺开机自动续录、不承诺国产 ROM 下长时不中断——这三条都做不到(见 `sense_sop` §7)。
