## §0 七条硬规则(r22 十一轮真机 run 全部踩到, 模型无关)

1. **每轮必带工具调用, 直到最终报告**。中途只发一段"我现在去看界面"之类的纯文本 = 宿主视为最终报告, 任务当场结束(r22 run1/run2: kimi-k3 两次在搜索框刚输完时纯文本收工, 任务 0 产出)。要么调工具, 要么给完整 final。
2. **宿主运行时提示是合法指令, 不是注入**。工具结果后出现的「Steps have been replanned」「已连续执行第 N 轮」「代码运行超时」等段落来自 GA 宿主, 照做; 不要因此中断任务(run1 T11 把它当 prompt injection 拒绝→任务夭折)。
3. **输入 ≠ 提交**。`paste()` 只把词放进框; 必须 `droid.key('ENTER')` 或 tap「搜索」键才进入结果页, 且**提交前回读框内文本**(run1/run2 都停在联想页; run3 T7 重搜时框内被热搜占位词替换成「乳此美好…」, 结果全错)。
4. **禁盲试坐标循环**。`for x,y in [(1010,35),(980,40),...]: tap` 这类"总有一个点中"写法, 会误触退回/切页(run3 T6 因此退回搜索页, 连锁出 T7 占位词事故)。定位一律 dump/ui_detect 拿到唯一候选再点(phone_use §0.5)。
5. **换道必声明**。GUI 卡住改用公开接口/网页拿到答案是允许的兜底, 但 final 必须写明「本结果来自 X 接口/网页, 非 App 内排序」并说明 App 现停在什么状态(run3 T8 用 api.bilibili.com 拿答案, final 却写成"按最多播放排序后第一个是…", 且 App 留在错误搜索词+筛选抽屉打开的污染态)。
6. **禁止复用历史答案当 final**。同类任务再次下达时, 上一轮的结果已过时且屏幕状态未知; final 只能引用**本轮**工具输出(phone_use §0.5)。零工具调用直接给结论 = 编造完成(run7: 会话上下文延续到新任务时, kimi-k3 9 秒 1 轮零动作, 照抄上一轮的 B站 结果并声称"全程停留在结果页"——屏幕当时根本不在 B站)。
7. **用户点名的 App 就是通道, 先 App 再兜底, 兜底不出数就说不知道**。「用顺丰速运查…」「在闲鱼搜…」这类原话 = 通道锁定: 第一步读 SOP、第二步 `launch` 该 App; 只有 App 内确实找不到入口/被墙(有轨迹证据)才换官网/接口, 且按 #5 声明。v8 顺丰运费任务反例: T1 直接 `webcdp.open_url(sf-express.com)`, 全程没打开 App, 网页超时后 final 给「经验参考 13～18 元 / 1～2 天」——**这是编数**; 同题跨 App 版先 App 后官网并写明「查询渠道: 顺丰官网」= 成功。拿不到就写「未查到」, 不许用"通常/大约/经验"补一个数。

## §1 API 返回形态速查(省掉每次 help() 的 1-2 轮; 权威仍是 droid.py docstring)

| 调用 | 返回 | 常见误用 |
|---|---|---|
| `pkgs('美团')` | `[{pkg,label},…]` | 直接把整个列表传给 launch(run1 T4) |
| `launch(pkg:str)` | dict; 之后 `ping()['pkg']` 核前台 | 传 dict/list |
| `dump()` | `[{t,edit,b,click,sel,l,cls,…},…]`, 坐标在字段 **`b`(字符串 "x1,y1,x2,y2")** 不叫 bounds(run12 T7 解析错误浪费 1 轮); **`sel:1` = 选中态**(tab/chip 高亮, XHS2 实证; 挂在文本子节点上, 容器只有 click); **`[]`=敏感置空信号**(非空壳) | 按 `bounds` 取坐标; 用截图颜色判 tab 选中(有 sel 就不用); 拿 `[]` 反复重试 |
| `shot()` | BGR ndarray(传 path 则落盘) | 当成 path 传给 ocr |
| `ui_detect(img)` | `[{bbox:[x1,y1,x2,y2],type,label,cls,confidence},…]` **是 list** | `detect.get('items')`(run1 T7) |
| `paste(text, replace=False)` | `{hit,uncertain,ime_hint,…}`; hit=True 才算上屏; **`replace=True` = 全选后粘贴(覆盖预填/旧值), hit 按框内==text 判** | 不看 hit 直接下一步; 对预填框用默认 paste(追加成「ozerGA测试」) |
| `key('ENTER')` | 提交搜索/发送 | 输完不提交 |
| `tap(x,y)` | `{diff,hint,fg}`; diff<0.05% 会带 hint | 不看 fg 就继续点 |
| `scroll_view('down',times=1)` | `{scrolled,uncertain}` | 传坐标当 swipe |

## §2 风控知识库(什么会触发 · 长什么样 · 撞上怎么办)

**风险主体**(gandroid-wechat-yolo / phone_use §5 已成文): 已启用的无障碍服务会被 App 枚举上报 + 注入式动作 + 行为模式; 不只是"那一次读树"。**降风险的唯一正道 = 减少动作总量 + 不在敏感 App 读树 + 一步一验 + 风控页立即交人**。不做时序伪装、不切输入法、不 ADB 注入、不自动登录/取码(phone_use §5 明令)。

### 2.1 风控/门禁信号(命中任一 → 停止自动化, 不重试, 报告用户)
| 信号 | 典型文案/形态 | 归类 |
|---|---|---|
| 身份验证 | 「身份验证」「验证码将发送到 1xx****xx」「获取验证码」「人脸识别」「刷脸验证」 | 风控核验(r22 run4 支付宝实证) |
| 实名核验 | 「验证微信支付身份信息」「填写姓名和证件号码」「实名认证」「绑定银行卡」 | 账号级风控(WX1 实证, 微信在纯视觉自动化 ~20 动作后自弹); **整任务终止**, 不填不试 |
| 强制登出 | 「账号状态异常，本次登录已失败」「请尝试重新登录，并根据弹窗提示操作」「你的账号在其他设备登录」 | **风控已升级到账号级踢下线**(WX3 实证: 实名核验页 ✕ 关闭约 1.5h 后微信自动登出并拒绝重登); 不点「确定」以外任何东西、不代登、不重试, **该账号后续一律禁自动化**, 交用户本人在手机上按提示重登 |
| 滑块/拼图/点选 | 「请完成安全验证」「拖动滑块」「按顺序点击」 | 反自动化 |
| 环境异常 | 「设备环境异常」「检测到风险」「账号存在风险」「请在常用设备上操作」 | 设备/账号风控 |
| 登录墙 | 「登录」「一键登录」「微信登录」「绑定手机」 | 环境前置(非能力失败, ≤2 次即停) |
| 安全键盘 | 输密码/支付密码时自绘键盘, dump 无节点 | 金融保护, **永不代输** |
| 防截屏 | `shot()` 连续黑帧抛 RuntimeError | FLAG_SECURE 页; 不在册 App 可退 dump bounds 导航, 关键步先问用户 |
| 系统门 | Google Play「要从 Google Play 下载额外的文件吗?」(Play Feature Delivery) | **安装类动作 → ask_user**(run4 实证, agent 正确停问) |

### 2.3 机型/系统差异(通用防御 + 已验证 OEM 表)
**通用防御(与机型无关, 违反即在别的手机上翻车)**: ①**永不写死坐标**, 分辨率/DPI/导航栏高度/刘海各机不同——每台机 `droid.screen()` 取 w/h, 坐标只来自当帧 `find/dump/look`; ②底部约 5% 屏高(手势条/三键栏)与顶部状态栏是系统热区, tap 落在其中会误触返回/多任务(droid.swipe 已自动夹取, tap 不会); ③深色模式/字体缩放会改变 OCR 命中与布局, 同一 App 两台机文本坐标不可复用; ④权限弹窗文案各家不同(「允许」「始终允许」「仅使用期间允许」「拒绝」), 按语义而非位置点, 只授任务必需的权限; ⑤OEM 桌面/分屏/悬浮窗会让 `launch()` 后 fg 不变, 先 `dumpsys activity activities` 看 display 归属(phone_use §4)。

## §4 提速手法(不牺牲验证)
- **一帧多取**: 同一 `shot()`+`ui_detect()` 里把 搜索框/排序入口/筛选图标 坐标一次采齐, 顺序 tap, 只在核销点重截(app_ops「迅速」节)。
- **dump 能用就不截图**: 美团/B站 dump 可用(text/edit 齐), 比 ui_detect 快且稳; 只在 dump 缺目标(自绘控件/SurfaceView)时视觉。
- **原子脚本**: 「tap 搜索框 → paste → key(ENTER) → sleep(2) → shot」放同一 code_run(跨 turn 一步 15-25s 延迟)。
- **别重读 SOP**: 已读过的 SOP 不再 file_read(run1 T11 想重读 phone_use); 约束写 checkpoint 即可。
- 预算参考(Pixel 10, r22): gpt-5.6-sol(最强档) ≈ 15-30s/轮(偶发 60-110s); 照剧本直达 8-10 轮 ≈ 3-4 min, 从零摸索 13-29 轮 ≈ 7-8 min(B站 13 轮=0.57u); 出口链路稳定时(XHS2, 每轮 TCP+TLS<0.4s) 11 轮排序读卡 = 155s ≈ 14s/轮; kimi-k3 纯文本收工风险高(§0 #1), 已停用。
