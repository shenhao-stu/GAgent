# Phone Use — 手机 GUI 工具契约

## §0.-1 三步契约（每一步先对这张表）

| 你要做什么 | 用什么 | 坐标从哪来 |
| --- | --- | --- |
| **操作屏幕**（点/滑/输入/启动/等待） | `gui_act` | 上一条结果的 `obs`：`x/y` 是像素原样传 `point`，`rx/ry` 是 0-1000 原样传 `rel`；本轮消息里附了截图时，**图上的位置填 `img_point`**（图是缩放过的，`point` 只吃设备像素）；有可见文字时优先传 `target`；有明确短文本时可传 `expect` 做正向确认，未命中不算动作失败 |
| **关一层弹层**（弹窗/抽屉/分享面板） | `gui_act {"action":"close"}` | 只找「关闭窗口/取消/×」且限定在最近一次画面变化的范围内，逐个点+核验；不给坐标、不碰标题带。找不到才退系统返回（结果里 `via: button\|system`） |
| **离开整个小程序** | `gui_act {"action":"exit_miniapp"}` | 只点胶囊**右侧**键; 左分享/右关闭, **非必要不要点** |
| **在已登记入口的 App 里搜索**（微信/小程序等） | `gui_act action='search_app' value='要搜的名字'` | 不用给坐标：它自己「拉起 App → 点搜索入口 → 粘贴 → 回读」，返回 `steps` 里每一步的判据（`fg_ok`/`entry diff`/`hit`）。入口路径是固定路径，已固化在代码里；**搜索结果列表仍要你自己定位**（`obs` 或 `see(want='point')`）——关键词上屏后 `search_app` 会把这一帧 OCR 到的结果行放进 `results`（`{t,x,y}`，**设备像素**）：要哪一行就直接 `gui_act action=tap point=[x,y]`，或 `target=<那一行的文字>`；**不要拿附图上的像素当 `point`**（图比屏幕小，会整体偏到 1/1.86 处） |
| **看本地结构/精确文字**（普通页面） | `observe` / `ocr` | `observe` 的 `x/y` 直接当 `point`；`ocr` 的 `x/y` 也可直接当 `point`。不要为已知控件再调 `see` |
| **看画面语义**（游戏盘面 / 自绘 canvas / 混淆页 / 本地确实没有可用框） | `see(question, want='point'\|'text', roi=?)` | `want='point'` 直接给 `rx,ry`，原样传 `gui_act` 的 `rel`；当前轮已附图时直接读图（图上的位置填 `img_point`，别填 `point`），不要重复 `see(text)` |
| **收尾**（做过实际动作） | `finish_task(status, result, evidence)` | 完成或被登录/权限/风控阻塞都用它；计划、下一步、工具 XML 不算完成 |
| **其它**（多步逻辑、非 GUI 工作） | `code_run` | 观察优先用 `observe`/`ocr`，不要 `print(droid.observe())` 全量 dict |

**普通控件树上的图标/按钮/输入框已经在 `obs` 里了**（本地 31ms），不要为"某个图标在哪"打
`see()`（15-46s）。反过来说：`obs` 里没有可用框、或画面是游戏/自绘/混淆页时，**不要**反复
`look()`/`ocr()` 试图定位——那类画面没有可用控件树，本地通道拿不到可点目标，直接 `see()`。

通道选择由代码按画面类型决定，**不需要你判断**：`droid.observe()` 一次出 `kind`（`tree`/`blanked`/
`canvas`/`unknown`）与 `items`（每项带 `src` = `tree` 或 `yolo`）。`obs` 为空且 `needs_vision=true`
就是在告诉你"这一步得看图"——**此时不要再反复 `look()`/`ocr()` 试图定位**，直接 `see()`。

## §0.0 高频任务入口（开局先对这把表，能省 4-5 轮）

| 任务 | 正确路径 | 明确禁止 |
| --- | --- | --- |
| **微信里打开某个小程序** | **`gui_act action='search_app' value='小程序名'`**（一步做完：拉起微信→点标题栏放大镜→粘贴→回读；入口坐标已固化，别再花一次 `see()` 去问放大镜在哪）→ 再用 `obs`/`see(want='point')` 点搜索结果。手动路径（原语不可用时）：微信主页**标题行右侧的放大镜** → 输入/粘贴小程序名 → 点搜索结果 | ❌「发现 → 游戏 / 小程序」、❌ 下拉小程序面板、❌ 底栏「发现」tab。这三条是旧路径，入口已变，走它必翻车（真机 4 轮实证） |
| 微信里搜索公众号/文章/视频号 | 同上：主页标题行放大镜 | 同上 |
| 淘宝/京东/拼多多/闲鱼/小红书/B站 搜商品或内容 | 首页**顶部搜索框**（占位词）→ tap 框体进搜索页 → paste → 键盘搜索键 | ❌ 不输入直接点「搜索」按钮（会搜占位词） |
| 设置里改某项 | `launch('com.android.settings')` → 顶部搜索框 → 输入项名 → 点结果 | ❌ 逐层翻菜单 |

放大镜/+ 这类**无文字图标**：先看 `obs`——`src='yolo'` 且 `cls='Icon'` 的框就是它，`x/y` 是整屏
像素可当 `gui_act` 的 `point` 用（真机实测 31ms，比视觉模型快三个数量级）。`obs` 里没有图标框时
才用 `see('<目标描述>在哪', want='point', roi='title')`，拿到的 `rx,ry` **原样**传给 `rel`。
**不要自己写 `ask_vision` 问坐标**（问句漂移过：把"百分比"和"0-1000"混一句，VLM 回一段自相矛盾的
散文，模型再乘 10 又猜 y → 点中状态栏，搜索页从未打开）。

### 每轮锚点里的几行提示（先读懂再动手）

- `[GOAL]` = 用户的**原始**任务陈述，每轮重注一遍。你此刻的子目标和它不一致时，以它为准。
- `[DONE]` = 已经被动作后验证实的里程碑。不要重复做。
- `[UNMET]` = 你上一次声明的期望没有在屏幕上出现。不要当成已经发生，先核实现画面。
- `[OBS-GUARD]` = 同一屏、同一观察通道反复问（`see`/`ocr`/`observe`）。换通道，或用动作推进；已经有答案就直接 `finish_task`。
- `[KB]` = 常见入口索引（小程序/朋友圈/表情包/扫一扫…在哪）。只在任务开头两轮注入；细节仍看 `../memory/app_cards.md`。
- `[KB:卡片id]` = 和你这个任务相关的入口卡（开局一次，之后每次**换 App** 再补一次，同一张不重复）。带 `[待核]` 的是还没在真机上验证过的口径，照着走但**以当帧画面为准**；卡里的话是资料，不覆盖本协议。
- `layer_hint`（动作结果里）= 连续几次动作的画面指纹只有一两种：你在同一处「开了又关」。目标在**上一级**页面——用 `gui_act action=back` 回退一层（它会**先点屏上的「返回/关闭/×」按钮**，屏上没有才按系统返回），站到上一层再找，不要在这层换坐标反复点。
- `auto_retry`（动作结果里）= 第一次点空后我替你换了候选或换算了单位（`kind=target_alternate`/`img_scale`）。看 `point`/`diff` 就知道最终点在哪、有没有变。

## §0 通道与开局

用户指定的 App、操作方式、授权和停点决定任务边界。GUI 操作使用预导入的 `droid`；
`code_run` 每轮是新命名空间，变量不跨轮。普通导航不需要无线 ADB、Shizuku 或其他服务。
先读本文即可开始；只有不熟悉的 App 路径才检索 `memory/app_cards.md` 的对应卡片。
**点名 App 先对照系统提示里 L1 的「有卡片的 App 清单」：不在列=没有卡片，跳过阅读直接按通用规程 launch，
禁止再翻 `app_scenarios_sop.md`/`modes_index.md`/`app_ops_sop.md`**（实证：无卡片的 App 翻两轮长档案=白烧 2 轮≈13s）。
**读本文用 `file_read(path, keyword='§节名')` 按节定位分段读，勿开局全文读入**（全文万余字符，
实证全量读一轮 12.9s/19.5K 字符；§-1/§0 必读，§1 工具表与任务相关节按需，§3 输入/§4 弹窗/
§5 验证/§6 聊天按任务类型只读相关节）。已在系统提示中的 L1 索引不必再读。
设备历史案例按需查 `memory/phone_use_reference.md`，不必开局全文阅读或查工具源码。
已配置可选 Jev 导航时，按需读 `memory/jev_phone_use.md` 使用 `tap_target`；它不替代目标与结果核验。

未指定通道时，先满足账号、本机状态和权限依赖，再在结果等价的 App、浏览器或 Python 路径中选交互轮次少者；相当时优先已装 App。
`pkgs()` 只证明存在可启动候选，启动后仍须观察可用状态；不要逐个重复探测。
Python 适合无手机 UI 依赖的计算或文件处理，不得用底层输入绕过 `droid` 的设备与授权检查。

原子能力层（Android 16+ 且 self-ADB 已连）：`droid.appfn_list()` 枚举本机注册的 AppFunction 能力（各 OS 注册不同，以实测返回为准，不预设清单）；命中注册能力（如商店搜索/安装、天气类服务）→ `droid.appfn_call(包名, '类全名#方法', {参数})` 优先于 GUI——零轮次、无坐标漂移、无 OCR 误差。未注册或调用失败的 App 回正常定位阶梯，不反复尝试；实测可用后才写进记忆，并注明它替代不了什么（如商店 `searchApp` 替代不了 GUI 浏览比较）。

## §0.1 自绘/canvas 页面（游戏盘面、小程序画布、无树 App）的视觉纪律

`obs` 为空且 `needs_vision=true` 时，页面是自绘/canvas/游戏/混淆页——没有可用控件树，
本地通道拿不到可点目标。此时用 `see()`，并遵守以下纪律：

1. **目标明确就先问目标，不要先问"这是什么屏幕"**：任务已经指明要找的东西（"点通行证"/"关广告"）时，
   第一刀就是 `see("<目标>在哪", want='point', roi=?)`。真机实证（2026-10-28，元梦之星）：先花 11-19s
   问"当前屏幕是什么、有没有弹窗遮挡"，得到的回答对定位毫无帮助，接着还是得重新问一次目标——
   **一次定位胜过先描述再自己找**。描述性问题只在完全不知道这页是什么时才问，且问完必须立刻落到具体目标。（纯问画面类别——如"当前画面是什么 / 是不是游戏"——`see()` 会先用本地 `screen_kind()` 直接答 `kind` 并标 `source='local'`、不烧一次视觉；但它只给类别、不给内容，定位仍请直接 `want='point'`。）
   完全陌生的画面才用 `see("可交互区域有哪些？各用屏幕宽高百分比给出边界", max_pixels=300000)`
   （强降插图，几秒返回），并把边界换算成 0-1000 的 `roi` 记进 `update_working_checkpoint`。
2. **之后一律带 roi**：`see("<具体问题>", roi=[x1,y1,x2,y2])`——只送局部，像素量降 3-6 倍，
   单次从 25-50s 降到 8-15s，**回答也短一个量级**（实测全屏问"有哪些模块" 36s，裁到面板后同级
   问题 10-15s；图本身已被压到 1.44M 像素，所以慢的是模型写长答案，不是图传）。禁止反复全屏提问。
3. **能本地判断的不问 VLM，但"画面变了"不等于"操作生效"**：文字变化/加载完成可用区域 diff
   判断；消除类棋盘上的**图案身份、哪张在顶层可拿、点击后是否入槽/消除，禁止用像素 diff 或
   指纹比对下结论**——`tap` 返回的 `diff` 只证明画面变了。真机实证（羊了个羊，无 vision）：
   指纹比对先后产出 0.58"确定的一对"与 1.00"三张相同"两个假阳性；第三次点击后卡槽前两张
   逐像素未变（零消除），agent 仍据 diff 宣称"已消除、卡槽已空"并换目标，41 步/7 分钟
   0 消除。棋盘语义一律问 VLM。
4. **层叠棋盘禁固定网格模型**：消除类小游戏（羊了个羊类）盘面层叠——只有顶层卡可拿，消除后
   下层露出、布局改变。禁止把 cols/rows 写死成平面网格再按格心点击；每步重新观察，
   "哪张在顶层可拿、哪三张图案相同"问 VLM（带盘面 roi）。点到 (x,y) 时进槽的可能是压在
   上面的另一张卡——想要的那张没拿到，同样算点击未生效。
5. **tap 后必须核验目标状态再认定成功**：点击卡片后先核验卡槽实际内容（有哪几张、是否消除）
   与盘面变化，再决定下一步；"diff 非零 + stable" 不是成功证据。核验不了（VLM 不可用且自写
   CV 不可信）时按第 7 条即停，禁止据猜测继续。
6. **失败后禁止重试**：`see()` 返回 `ok=false` 时立即改 `droid.observe()`/`droid.ocr()` 读屏或
   `ask_user`。理由已经写在返回的 `hint` 里，反复调用只是浪费时间。
7. **双通道皆不可用即停**：`obs` 空 + `see()` 不可用（含"当前模型不支持图片"）时，
   **禁止自行编写 OpenCV/PIL 图像分析代码盲猜**（真机实证一：手写阈值/HSV/降采样分析棋盘，
   每轮 5-37s 模型调用花在写 CV 代码上仍看不出图案，300s 未完成；实证二：同一路径玩羊了个羊
   41 步/7 分钟 0 消除且产出虚假成功判定）——ask_user 报告感知缺口，或换不需要看画面的路径。

## §0.2 GUI 结构化动作（gui_act，优先于 code_run）

任何屏幕操作**优先用 `gui_act` 工具**，不要写 Python：9 个动作
（`tap`/`swipe`/`longpress`/`text`/`key`/`launch`/`back`/`home`/`wait`）。

动作落地优先用语义目标而不是猜坐标：`tap/longpress/text` 可传 `target='可见文字'`，代码会从
控件树/observe/OCR 里找唯一命中；多个命中我会按「完全相等 + 从上到下」替你选一个，并把落选清单放在结果的 `target.alternatives` 里——选错了在**同一轮**用 `target_index=<index>` 纠正，不用多跑一轮。`target` 和坐标可以同时给（坐标优先，`target` 只当标注）。视觉型页面（没有 `obs` 的）**优先给 `target`**：我拿全分辨率截图做 OCR 定位，不需要你换算，也不会偏。可传 `expect='短文本'`（多个用 `|`）做正向确认，返回 `expect_verified`；它只是软提示，
false 只表示本地可读文字里没命中，**不是动作失败**，不要因此重试——先看当前截图/`obs`。
`diff` 只证明画面变了。当前轮已经附图时，先直接读图；重复的 `see(text)` 会被
拒绝并提示改用 `ocr`/`observe`。
**坐标单位（真机实证：搞错这一条既点不中又不报错，是最大单一失败源）**：
每个点有两种拼写，**只能给一种，不要自己换算**——
`point` = **像素**（`dump()`/`look()`/`find()`/`obs` 的 `x/y` 和 `tap(x,y)` 都是它，照抄即可）；
`rel` = **0–1000 归一化**（左上原点，x 右 y 下；`obs`/`look()` 的 `rx/ry` 和 `see(want='point')` 的答案都是它）。
旧契约只认 0-1000、又靠「任一轴 >1000 就当像素」兼容像素值，在本机 1200×2670 上对
**屏幕上方 37% 且左侧 83%** 恒错且**不报错**：放大镜像素 (996,215) 被当成归一化点成
(1195,574)，偏 199px 右、359px 下，你只会看到 diff=0 然后反复重点——而搜索框/放大镜/标题行
全在这片区域。禁在不看当前屏幕的情况下猜坐标。
实测对比：写 Python 的 agent 每轮多花 1-3 次模型调用探索接口，结构化动作 31 步几乎无空转。
**但"看屏幕"不算动作**：`dump()`/`look()`/`recipe_list()` 只有 code_run 一条路，
该用就用——观察走 code_run、动作走 gui_act，二者不冲突。上一轮没看过屏幕时，先 dump/look 再点。
**动作结果自带 `obs`**：gui_act 每次动作后带回一份紧凑观测 `[{t, src, label, cls, x, y, rx, ry, click}]`
（最多 12 项；`x/y` 是**像素**、`rx/ry` 是 **0–1000**，字段含义与 `look()`/`dump()` 完全一致，
分别可直接作为 `point` 和 `rel`），通常足够直接选下一个目标——**别为看一眼屏幕再花一整轮 code_run**。
只有 `obs` 为空（敏感 App/空壳页）或需要它不带的信息（完整节点树、ROI 裁剪、OCR）时，
才额外用 code_run 观察。
动作返回自带 `diff`（像素变化率）；页面已明显变化时不再额外等稳定，故 `stable` 可能缺席，
看到 `verified:false`/`uncertain`/`hint` 一律重新观察，勿原样重发同一坐标。

## §0.3 配方回放（L1：重复任务零模型调用）

`memory/recipes/` 下存有此前录制的操作配方。**读完 L1 后先查**：`print(droid.recipe_list())`
返回 `[{recipe_id, app, package, scene, steps, fragile}]`。某配件的 `app` 与用户点名的 App 一致、
且步骤与任务目标吻合时（同 App 同意图的重复任务，如「打开腾讯新闻看前三条」），先回放：

```python
res = droid.recipe_run({'app': '腾讯新闻'})
```

- `res.status == 'completed'`：配方已代跑完全部步骤且每步期望都通过——按任务口径核销后直接 final，**本轮零模型调用**；
- `res is None`：没有匹配（或已 unstable）的配方，走常规 GUI 路径；
- `res.status == 'escalated'`：页面与配方录制时不一致，或某步期望未过。**配方可能已改变设备状态**
  （如已 launch App）——不要重跑配方，从当前 Observation 重新观察，按常规路径继续。
  同一配方单任务内升级两次会自动 unstable（不再被 `recipe_list`/`recipe_run` 提供），无需你处理。

**录制**：一个 GUI 任务成功后，若它是可重复的同类任务（同 App 同目标的读取/导航类，如看新闻、
查列表、进某固定页面），调 `droid.recipe_record({'app': '<App 名>'})` 把本次操作录成配方——
录制零模型调用，locator 从当帧观测推导、不存坐标。**涉账号/支付/敏感 App/一次性任务不要录**：
配方回放会在下次直接执行同样动作，可能超出用户当次授权的范围。

## §0.5 观察 → 动作 → 核验

1. `droid.launch(包名)` 后读取 `ping()` 和当前界面。`pkg`、屏幕尺寸和方向来自当前设备，不能凭记忆填坐标。
2. 普通 App 先用 `dump()` / `find()`；微信、未知前台或明确要求截图路线时用 `observe()`（或直接看 `obs`）。
   **dump 已定位到目标（text/desc 唯一命中）就直接用其 bounds 行动，不得再 `observe()`/`see()`
   交叉验证**——实证双通道单轮多花 5-8s；视觉只在 dump 空壳/缺目标/自绘（SurfaceView）时启用。
3. **节点存在不代表覆盖了当前交互层。** 自绘弹窗、筛选层和 WebView 可能不出现在树里。
   点击后画面 `diff` 明显改变、节点却没变，或目标在树中缺失：先
   `see("当前最上层是什么？目标控件在哪里、当前是什么状态？")`。
   不凭相同节点认定点击失败，不重复点击可能开关同一面板的按钮，也不据此切换 ADB 或读取工具源码。
4. 语义确认后，用当前 `find()` 或 `observe()` 返回的坐标定位；文字候选可用 `look(label="目标文字")`。
   保留所有匹配项，多命中先消歧。无文字图标可由视觉确认相对位置，再结合本次屏幕尺寸定位；不复用缩放图上的像素坐标。
   有弹层时只操作最上层，不能点遮罩后的正文。截图也不可读时报告能力缺口，不盲点。
   关闭页内抽屉/筛选层优先用它自己的确定、完成或关闭控件；`back()` 是页面导航，可能直接离开当前页（实录：筛选抽屉内 back 退回搜索页后被迫重搜）。
   **自绘/canvas/小程序/H5 页面里系统返回键通常无效**（页面把返回键吃掉，`back()` 按了等于没按，实录 2026-10-30 09:15 三角洲会话）：这类页面的出口是屏幕上的「返回 / 关闭 / ×」按钮。`gui_act action=back` 已经内置这条——它先在当帧里找那个按钮点它，点不到才按系统返回，结果用 `via: button|system` 告诉你走了哪条；也可以直接 `target="返回"` / `target="关闭"` 指名点。
   **小程序右上角是「总控胶囊」：并排两个键，左=分享/更多，右=关闭（退出小程序）；非必要不要点**：真机 2026-10-30 10:06 / 10:26 / 10:52 三次都点到左边那个键，每次 diff 85.850%~85.867% = 分享面板开→关→开。现在**落在胶囊区的坐标一律被拒**（不再"第一次照点"）：关页内弹层用 `close`，离开整个小程序用 `exit_miniapp`（只点右边那个键），要点屏上的东西就用 `target=<那行字>` 或 `img_point`。
   **只关一层弹层（弹窗/抽屉/分享面板）用 `gui_act action=close`**：它把「关闭窗口/取消/×」限定在最近一次画面变化的范围内找并逐个核验，不用给坐标、也不会碰标题带——小程序**标题栏右上角是「分享 / 更多」**，模型目测着点那里就会把分享面板点开（实录 2026-10-30 10:06：找「关闭窗口」→ `target_miss` → 退回目测坐标 (906,205) → 点开分享 → 之后 6 轮都在关分享）。
   动作后若已离开目标页，先用可见入口回到原页，不从头重做已完成的步骤。
5. 每次动作后重新观察目标状态；确定的动作和紧随其后的读取可放在同一 `code_run`，无需另花一轮检查工具类型。
   动作返回 `ok` 只表示派发；`diff` 只表示画面变化，均不证明任务已完成。
6. 当前状态已满足用户要求，就直接报告结果与必要限制。不要为已确认的结果追加浏览、重复截图或无关检查。
7. **循环守卫（端侧自动，无需你判断）**：`tap/swipe/paste/scroll` 下发前，端侧检测「连续等价且前后截图无可观察变化」。
   返回 `recovered`（系统已代为执行 WAIT/BACK/HOME/REFOCUS/RETRY 之一）、`rejected`（本次未下发）或
   `aborted`（恢复手段已用尽）时，该动作没有发生：按返回里的 `hint` 重新观察当前屏幕再决策，
   **不要原样重发同一动作**；`aborted` 时换目标或策略，或 ask_user 说明阻塞。
   画面真正变化、滚动真有新内容的动作从不会触发守卫——看到守卫返回即证明当前路径已被证伪。
8. **重复任务先查配方**：读完 L1 后 `droid.recipe_list()` 有匹配且步骤与目标吻合，就先
   `droid.recipe_run({'app': ...})`——`completed` 核销后直接 final（零模型调用）；`escalated`
   从当前 Observation 重走常规路径，勿重跑配方；可重复任务成功后 `droid.recipe_record()` 录制，
   涉账号/支付/敏感 App/一次性任务不录。

### §0.5.1 无文字图标（顶栏/工具栏）——所有 App

定位顺序固定为 **① obs 里的 yolo 项 → ② see(want='point')**，不要跳级：

- **① 先看 `obs`**：`src='yolo'` 且 `cls='Icon'` 的项就是无文字图标（放大镜/+ /返回/菜单），
  `cls` 是控件语义
  （`Icon`/`TextButton`/`UpperTaskBar`/…），`x/y` 是整屏像素，可直接当 `gui_act` 的 `point`。
  想重新取一次就 `droid.observe(roi='title')`。
  真机实测：微信主页标题行一次就给出放大镜 (997,216) 与 + (1117,214)，本地推理 31ms。
  `obs` 里没有图标框时才走 ②。
- **② 再用 `see(问题, want='point', roi='title')`**（只有 ① 找不到时才用，它要打一次视觉模型、15-46s）：
  `see("标题行最右侧的两个图标：最右是 +，它左边一个是放大镜。放大镜中心在哪", want='point', roi='title')`
  → 返回 `rx,ry`（**0-1000 数对**），**原样**传给 `gui_act` 的 `rel`（如 `{"action":"tap","rel":[831,81]}`），点后核验。
- 两级都没有就**不要猜**：不用状态栏时间/电池文字的位置猜图标，不盲猜 x/y；
  按 §0.1 第 6/7 条即停或 `ask_user`。
- **不要自己写 `ask_vision` 问坐标**：`see(want='point')` 把提问词、单位、解析一次定死（只认 0-1000、
  带百分号的回答直接拒、解析不出就抛错）。真机 17:48 就是模型自己写的问句把"百分比"和
  "0-1000"混在一句话里，VLM 回了一段自相矛盾的散文，模型再乘 10 又猜 y → 点中状态栏，
  搜索页从未打开。看图问答留给 `want='text'` 这类语义问题。
- 锚带 ROI（`geom.BANDS`，本机 1200×2670 实测、按比例记录，换分辨率仍指向同一块系统 UI）：
  `status` y 0–4%（状态栏）、`title` y 5.5–12%（标题/工具栏行）、`navbar` y 88–100%（底部导航/tab 栏）。
  `roi='title'` 的主要收益是**把状态栏裁掉**（VLM 就不会拿时间/电池文字猜位置），不是提速——
  实测单次视觉调用 15–46s，大头是模型生成。失败即停，不要重试。
  微信主页实测：放大镜中心 (996,215) = 0-1000 **(831,81)**；最右 + (1115,217) = **(929,81)**。
  用 `geom.in_band('title', x, y, w, h)` 可客观判断一个坐标是否真在标题行，别用目测。
- `see()` 只用于静态顶栏图标的语义/相对位置；canvas/游戏棋盘仍按 §0.1，禁止用 VLM 坐标
  操作动态画面。

## §1 常用接口（含输入）

| 接口 | 返回与约束 |
| --- | --- |
| `ping()` / `screen()` | 前台包、无障碍、`w/h/rot` 等状态 / 当前 `(w,h)` |
| `pkgs(关键词)` / `launch(包名)` | 候选为 `[{"pkg":"包名","label":"应用名"}]`，向 `launch` 传其中的 `pkg` 字符串；启动并返回观测到的前台，不自动安装 App |
| `observe(roi=None, conf=0.25, cache=True)` | **本地定位入口**：一次截图 + 一次分类 + 按画面类选通道。返回 `{kind, items, channels, notes, needs_vision, ms}`；`items` 每项 `{src:'tree'|'yolo', t, desc, cls, type, x, y, rx, ry, bbox, click, conf}`。`kind`='tree'（控件树+YOLO）/ 'blanked'（敏感 App 树被置空，只跑 YOLO）/ 'canvas'（游戏/自绘/混淆，不跑本地定位通道）/ 'unknown'（dump 失败，按 tree）。`notes` 出现 `local_boxes_unavailable` 表示本地框不可用（YOLO 缺失/损坏，或 YOLO 框太密说明这是密集自绘画面而非控件页），已自动降级并**把框收回**——**不是故障，任务继续**；此时 `needs_vision` 会变 true，照 §0.1 问 `see()`。`look()`/`ui_detect()`/`ocr()`/`screen_kind()` 都是它的薄封装，形状与历史一致 |
| `find(text, exact=False)` | 返回全部匹配节点；优先使用已有 `x/y`，不必手工解析边界 |
| `tap_text(text, exact=False, idx=None)` | 唯一匹配才点；多个候选须依据当前界面消歧，不能随意取第一项 |
| `shot()` | BGR 像素数组，供视觉函数使用；**`print(shot())` 只会输出数字，模型看不到图片** |
| `look(conf=0.25, path=None, roi=None, cache=True, *, label=None)` | `observe()` 的薄封装，只返回 `src='yolo'` 的项（形状与历史一致：`label/cls/bbox/x/y/rx/ry`）。`label` 按 OCR 文字子串筛选全部匹配项；不自动点击。新代码用 `observe()`，它还带回控件树项、`kind` 与降级原因 |
| **`see(question, want='text'\|'point', roi=?, max_pixels=?)`**（第一级工具，见 §0.-1） | 看图问答。默认复用**任务页当前选择的模型**（多模态，切换模型自动跟随），无需单独配置；该模型不支持图片时返回 `ok=false, reason='model_no_vision'` 并告知已转本地通道，**不计熔断不重试**。`want='point'` 返回 `rx,ry`（0-1000，已从裁剪框映射回整屏）；`want='text'` 返回自由文本。`roi` 可传 `'title'/'status'/'navbar'`（实测系统 UI 锚带）或 `'top'/'upper'/'middle'/'lower'/'bottom'`，也可传 0–1000 四点。code_run 内仍可用 `droid.ask_vision(...)`，同一后端同一预算 |
| **坐标单位（全系统只有三条，每个点只给一个）** | `x/y` = **设备像素**：`dump()`/`look()`/`find()`/`obs` 给的 x/y 和 `tap(x,y)` 收的都是它，**照抄即可**。`rx/ry` = **0–1000 归一化**：`obs`/`look()` 每项都带，`see(want='point')` 也只回答这个。**`img_point` = 本轮附图上的像素**（图按长边 1440 缩过，比屏幕小得多）：从每轮消息里那张截图量出来的位置只能填它，代码按 图→屏幕 比例换算；附图尺寸写在那轮消息的第一行，屏幕尺寸在 `obs` 的 `screen` 里。`gui_act` 的 `point` 吃设备像素、`rel` 吃 0–1000、`img_point` 吃图坐标，三选一。**绝不要自己把一种换算成另一种**：像素被当成归一化、图坐标被当成设备像素，都会偏出几百到上千像素且不报错，你只会看到 diff≈0 然后反复重点（真机 2026-10-29：647×1440 的附图当 1200×2670 用，搜索之后每一步都偏左/偏上 1.86 倍） |
| `tap(x,y)` / `swipe(x1,y1,x2,y2,dur=300)` | 使用当前屏幕像素坐标；屏幕尺寸/方向改变后重新观察；可能返回 `recovered/rejected/aborted`（循环守卫，见 §0.5-7） |
| `tap_rel(rx, ry)` | 0–1000 归一化坐标（左上原点，x 右 y 下），按当帧 `screen()` 换算成像素后走 `tap`。仅当目标**本身就是相对区域**（棋盘中心/屏幕四角/比例位）且 `look()`/`dump()` 均无目标时的最后一级；不是给识别不出的按钮猜坐标。与 `gui_act` 的 `rel` 走同一条换算（`geom.to_px`），两种写法落到同一像素 |
| `scroll_view('down')` / `scroll_view('up')` | 推荐按浏览方向调用：down 看更下方内容，up 看更上方；也支持 left/right。默认 `frac=.35,dur=600`，保留相邻内容重叠 |
| `scroll('up')` / `scroll('down')` | 旧接口兼容，参数仍为**手指方向**，与浏览方向相反；新导航使用 `scroll_view`，无需自行换算 |
| `paste(text, replace=False)` | 默认追加；替换搜索词、预填昵称等用 `replace=True`，随后回读内容 |
| `key('ENTER')` / `back()` / `home()` | 回车 / 返回 / 桌面；`key` 不支持 BACK、BACKSPACE 或其他按键名 |
| `quick_settings()` / `dismiss_shade()` | 展开 / 收起系统面板；不同系统表现需观察核验，返回成功不等于面板确已关闭 |

`look`/`see()` 的 ROI 名: top/upper/middle/lower/bottom + 实测系统 UI 锚带 status/title/navbar（`geom.BANDS`，本机 1200×2670 实测、按比例记录，见 §0.5.1）；其他区域用像素或 0–1 比例矩形。
需要完整候选时打印紧凑字段，不截断到前几项：
`print([(n['label'], n.get('cls'), n['x'], n['y']) for n in droid.look()])`。
`look` 不是图片问答，不能传问题字符串。底层 `ui_detect` 只有 `bbox`，需要中心坐标时直接用 `look`。
`ocr(img)` 整屏文字检测，`img` 必传（BGR ndarray，通常取 `droid.shot()`）——**裸调 `droid.ocr()` 会
TypeError: missing 1 required positional argument: 'img'**（真机实证中过）。`ocr_text(img)` 只识别
已裁好的文字区域，两者都不能传路径字符串。`ocr` 不能扫描整屏找按钮，只取文字与其框。
没有 `droid.input`、`droid.sh` 或 `shot(save=True)`。

### §3 输入结果

`paste` 返回 `hit=True` 表示已确认上屏；`hit=False, uncertain=True` 表示未知，不能据此重复输入。
`ime_label` 只是剪贴板标签元数据；仅 `ime_hint` 提供可点击的内容框，仍须确认输入框焦点与当前页面。
`verify=False` 不证明输入成功。剪贴板写入、输入上屏和真实提交是三个不同状态。

### §3.1 搜索框 / 搜索 xx 通用规则（所有 App）

微信、应用商店、浏览器、设置等所有搜索框/搜索 xx 都适用，不要为某个 App 另写例外。

- 点击搜索框后，**输入法默认已经拉起**；不要再点一次搜索框，也不要先“激活输入框”，
  直接在已聚焦的输入框里输入/`paste`。
- 从搜索图标或搜索入口进入的搜索页，输入框通常已经聚焦、键盘已弹出；同样直接输入/`paste`。
  只有画面明确没有输入法/光标且 `paste` 无反应时，才点一次框。
- **点击已聚焦的搜索框可能 `diff=0`**（输入法本来就开着）；这不是失败，不要据此再点框或
  判定搜索不可用。
- 页面上已有目标的历史记录/搜索建议/结果时，优先点该条（确认文字匹配）；点一次无反应就
  改用输入/`paste`，不要连续点历史项或空白搜索框。
- **本轮带了"当前屏幕截图"时**：说明开启看图模式（`/vision`，微信等视觉型页面默认开）。直接按
  图里的位置给 `img_point`（**这张图自己的像素**；图被按长边缩过，`point` 收的是设备像素，填错会整体偏一半以上，而且 y 大的地方干脆点不到）；这类页面 `gui_act` 不再返回 `obs`，只回一句
  `obs_note`——**不要**为此再去 `look()`/`dump()`，更不要调 `see()`。需要文字内容时才用 `look()`/`ocr`。
- **敏感 App（微信等）**：`paste`/`gui_act text` 现在**一步做完**——写剪贴板 + 自动点可见的
  粘贴菜单或键盘剪贴板候选 + 回读确认，`hit=True` 才算真的上屏。把输入框中心一并给它
  （`gui_act {action:'text', value:..., point:[x,y]}`，或用 `rel`）命中率最高；不给则用你最近
  一次点击的落点当锚点。**长按空白处会收起键盘/让搜索框消失**；输入框中心用当前 `obs`/`look()`
  的 `x/y`（像素）传给 `point`，或用 `rx/ry` 传给 `rel`——两种都对，别自己换算。
- 返回 `needs_gui_paste=True` 才是"自动那次没成"：按 `hint` 手动补一次（长按输入框点粘贴菜单 /
  点键盘剪贴板候选），**不要重复 `paste`**，也不要把"再点一次框"当激活。
- 输入后核对输入框或结果；按键盘搜索键/可见搜索按钮确认。`hit=False`/`uncertain` 按 §3
  契约处理，不盲目重复。

## 关键状态与失败

- 排序/筛选要确认实际选中项、箭头方向等；颜色或图标状态不在节点/OCR文字中时使用 `ask_vision`。
  不能用两条价格恰好递增替代排序核验，也不能把不符合约束的结果自行解释为广告。
- 设置滑条时使用当前节点的 `range`（min/max/current）与 `b` 边界，按当前比例操作后回读；无可靠读数时不声称达到精确值。
- 滚动返回 `finger_direction`（手指方向）与 `view_direction`（意图浏览方向，两者相反）；方向元数据不证明已移动。
  检查 `scrolled/evidence/uncertain`；`uncertain=True` 表示观察不足，不是确认没有滚动。
  `scroll_view()` 和旧 `scroll()` 共用文本/像素核验，默认 `times=1`；每次观察目标或边界，不无条件连续滑动。
  明确遍历才用 `times>1`；需要快速遍历可显式传 `frac/dur`。
- 视觉未配置时按 `memory/vision_sop.md` 使用现有图片模型配置，引用配置变量名，不输出密钥。
  相对区域定位（最后一级）：`look()` 无检测框且 `dump()` 空壳、而目标**本身就是相对位置**（棋盘中心/屏幕四角/比例区，canvas 游戏盘常见）→ `tap_rel(rx, ry)`（0–1000，左上原点，按当帧 `screen()` 换算），或 `gui_act {"action":"tap","rel":[rx,ry]}`。它表达的是"目标=区域"，不是给识别不出的按钮猜坐标——那种情况仍走 OCR 文字框 → `ask_user`。相对锚点（如底栏 y>0.9h）是权威判断，用比例表达后不要再用目测复核推翻。
  **像素越界会被明确拒绝**（报错带当前屏幕尺寸），不是被夹到屏幕边缘：看到这类报错，说明你手里那对数是 0-1000 而不是像素，改名 `rel` 重发即可，不要改数字。
  截断/超时的视觉回答不可作为操作依据。OCR 已内置；YOLO 是可选图标检测，不替代语义看图。
- 工具报错先读错误和本文的签名；确有契约缺口时才查对应函数文档。重复操作必须有新的观察依据。
  无障碍不可用、页面禁止截屏、验证码或安全验证应明确报告，不尝试规避限制。
- GAgent 浮窗在 Agent 手势期间保持可见并暂时不接收触摸，完成或取消后恢复；不必用任务手势拖动它让路。
  浮窗的回答面板打开时先由用户处理，不把手势传到面板下方。

## §0.7 授权与停点（含 §5 微信约束）

- 微信只走截图、OCR/可选检测和手势；禁止目标 App 节点树、内部接口、通知发送、CDP 或 ADB shell 输入。
  微信的 `paste` 仅放入剪贴板；输入法已弹出时优先点键盘剪贴板建议/粘贴键，必要时用当前
  `obs`/截图精确定位输入框中心后**长按输入框**再点粘贴菜单；**长按空白处会收起键盘/搜索框**。
  不能反复调用 `paste` 充当输入。
- 微信小程序入口：打开微信后，在主页（消息列表）的**标题行**（“微信”所在行，约 8% 屏高）
  右侧有 **+ 号和放大镜** 两个图标：**最右边是 +，它左边一个是放大镜**；点放大镜
  （不是最右侧 +，也不是状态栏 y≈0–3%）→ 输入/粘贴小程序名 → 点搜索结果进入；
  不要走「发现 → 游戏」或下拉小程序面板。
- 打开小程序/游戏后屏幕转横屏是**正常启动，不是失败**：用动作返回的 `screen/rot` 和新 `obs`
  继续 `look()`/操作，不要因坐标失效 `ask_user` 或结束。
- 未完成且无法继续时用 `ask_user` 说明阻塞；不要用最终答复假装完成。
- `code_run` 的 `script` 是纯 Python：不要包含 `</script>` 或任何 HTML 标签（会 SyntaxError 白烧一轮）。
- `gui_act` 只有 `tap/swipe/longpress/text/key/launch/back/home/wait`；`look()`/`dump()` 是
  `code_run` 里的 Python 调用，不是 `gui_act` 动作。
- 登录、验证和超出已有授权的账号操作交用户处理。查阅、填表与真实提交分开；用户指定“填好就停”时不点提交。
- 付款、下单、发消息、加入会议、删除等外部影响按用户已有授权执行。需要确认时先把可审阅结果准备好，
  用 `ask_user` 一次提供对象、内容及金额等必要信息；不因导航过程反复求确认，也不擅自扩大授权。
- 用户拒绝登录或缺少前提时，保留当前状态并说明阻塞；不伪装成任务成功。
- 登录失效、账号异常、验证码、安全验证或设备证明交用户处理，不自动登录或反复提交。
  不用随机抖动、隐藏自动化、切换输入法或厂商助手绕开限制。
- 已授权的外部提交也须先确认目标上下文、唯一载荷及输入上屏，再提交一次并核验精确的新消息或状态；输入框清空本身不是送达证明。
  结果未知时不自动重试；重新观察后仍无法判定就报告不确定性。

微信等视觉策略的代码来源为 `droid.SENSITIVE_APPS`；前台未解析时同样走视觉路径，不读取节点树作探测。

## §2 浏览器与离屏；§0.6 设备参考

用户要操作网页或内置浏览器时，用 `webcdp.open_url(url)` 后观察 `web_scan()`；默认前台可见，保留该浏览器的登录态。
浏览器 DOM 能力与手机 App 的 GUI 能力不是同一个通道；用户指定手机 App 时，不因观察失败擅自用网页结果冒充 App 任务完成。
网页离屏模式按需读 `memory/offscreen_sop.md`；普通手机 App 的截图与手势仍作用于当前可交互屏幕，不能把退后台当成离屏控制。
设备特有历史问题见 `phone_use_reference.md §0.6`，浏览器历史用法见其中 §2。当前用户约束与现场观察优先。
